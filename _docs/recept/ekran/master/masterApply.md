# `masterApply` · букинг мастера: одна дата за 100 ฿

**Зритель:** любой, кто вошёл через Telegram, — членства НЕ нужно (фича 3
`Cafe13KPG#1009`, решения владельца №35, №36; дверь — фича 1, `../dver/home.md`).
Условие подачи одно: на счёте хватает денег на букинг слота.

⚠ **Предусловие выкладки: клиент фичи 3 — только после api #176 в бою
(`/health` ≥ `fc474be`).** До #176 `event_live` требует членства организатора
и прячет ивент мастера без членства — новичок заплатил бы 100 ฿ за невидимый
ивент. С #176 ивент виден после одобрения арт-директором (фича 4);
порядок — `Cafe13KPG#1009`.
Право — подать букинг на свободное время календаря со СВОЕГО счёта. Решает
арт-директор на `masterReq`.

Шаг 4 «Вход в клуб как мастер», новая модель — слово владельца 20.11.2026:
«Он букает только один ивент теперь. На следующую неделю надо букать
следующий»; «Сколько угодно — каждый по 100 ฿» (ТЗ `Cafe13KPG#985`, редакция 2).

⚠ **Код клиента не читался** (правило `Cafe13KPG#975`). Форма ответов — снимок
сервера в `#985` (api `d75c445`); слова — выбор
дизайнера. ⚠ **Рецепт идёт ВСЛЕД сборке** (`#365`, v174) — ошибка постановки,
названная координатором; рецепт — основание описи и мера расхождения.

⚠ **Фича 3: плата видна ДО подачи** — `M1` под заголовком и `M6` у кнопки
стоят всегда, до нажатия `M8`; 100 ฿ списываются В МОМЕНТ подачи (ТЗ фичи 3),
поэтому сумма не может появиться впервые в отказе или после.

⚠ **`M12` — свой текст, а не `M9`** (дробление фич 3–8): деньги — `M12`
словами клиента, со ссылкой на пополнение; прочее — `M9` словами сервера.
Отказа по членству больше нет. Форма отказа по деньгам — снимок сервера
`master-request-409-no-money-no-membership` (api `#173`,
`app/routers/master.py:402–406` на api `main 56819f6`; в бою api ещё
`65e62d8`, выкладку ведёт devops): **409** со словами
`на счёте {balance}, а букинг стоит {amount}: не хватает {разница}`.
⚠ **Кодом его НЕ отличить:** тот же POST отдаёт 409 и на занятое место,
выключенное место и прошедшее время (`master.py:236`, `:389`, `:393`) — это
`M9`. Признак `M12` — слова сервера начинаются с `на счёте ` (контракт —
снимок; своего кода серверу не ставят, решение в `Cafe13KPG#1009`). Прочие
три 409 начинаются иначе: `место «…» занято`, `место «…» сейчас не
используется`, `это время уже прошло`.
`M12` — ключом перевода (№22, вид `<экран>.<блок>.<слот>`, словарь
`js/00-slova.js`, функция `slovo()`); прежние слова экрана этой фичей не
переводятся.

⚠ **Что будет со 100 ฿ при ОДОБРЕНИИ — экран НЕ обещает:** вопрос владельцу
№46 открыт. `M1` говорит только об отказе («откажут — деньги вернутся на
счёт») — это верно и до ответа (ТЗ фичи 3: при отказе возвращаются).

⚠ **`100` в разметке нет: число — адресом** (`/master/price` → `amount`).
Цена от часов не зависит, но клиент её не знает — знает сервер.

⚠ **Дата не подставляется из прошлого букинга** — остальные поля подставляются
(`#697`): прошлая дата всегда в прошлом или занята этим же мастером.

## Данные экрана

- `GET /master/price?hours=H` → `amount`;
- `GET /master/slot-busy` ОДНОЙ даты: `busy[]`, `conflict`, `fits`; ответ о
  другой дате не принимается (пользователь успел сменить дату);
- `POST /master/request` `{title, about, seats, place_id, starts_on, start_local, hours}` —
  без `weekday`;
- остаток счёта — тем же источником, что шапка.

## Состояния

| состояние | что на экране |
|---|---|
| **свободно** | `M3` «В этот день свободно», `M6`, `M8` жив |
| **пересекается** | `M4`; `M8` жив — свободу проверяет сервер, `M9` скажет отказ |
| **время прошло** | `M5`, `M8` погашен |
| **не хватает** | `M7`, `M8` погашен |
| **название пустое** | `M11`; запроса нет, поля сохранены — единственный `.deny` в демо |
| **отказ по деньгам** | `M12`; поля сохранены |
| **отказ сервера, прочий** | `M9`; поля сохранены |
| **занятость не загрузилась** | `Занятость не загрузилась` и `Повторить`; `M8` жив — сервер проверит сам |
| **цена не загрузилась** | `Цена не загрузилась` и `Повторить`; `M8` погашен — без цены не сказать, сколько спишется |

⚠ «Пересекается» НЕ гасит кнопку — ВЫБОР: из двух (гасить по `conflict` /
отдавать серверу) взят второй, потому что `conflict` снят до нажатия и
стареет. Отменяется, если люди жмут и получают отказ чаще, чем меняют время.
