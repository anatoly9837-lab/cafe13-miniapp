# `home` · блок «Ваши букинги»: свои букинги списком

Рецепт БЛОКА внутри чужого экрана, поэтому имя файла — ключ ХОЗЯИНА (`home`).
Форма подачи — `masterApply.md`.

**Зритель:** член клуба, не гость — тот же, кто видит `M0` «Забукать». Право —
видеть СВОИ букинги (`GET /master/requests/mine`). Чужих букингов здесь нет.

⚠ **Код клиента не читался** (правило `Cafe13KPG#975`). Форма строки — снимок
сервера в `#985` (api `d75c445`); слова — выбор дизайнера.

## Вход / Выход

| откуда / куда | как |
|---|---|
| вход | вкладка «Клуб» |
| `M0` «Забукать» | `masterApply` — ВСЕГДА, при любом числе ждущих |
| строка букинга | никуда не ведёт — ВЫБОР: всё, что о букинге знает мастер, стоит в строке; отменяется, если появится действие над букингом (отмена своей ждущей) |

## Слова

| что | слово |
|---|---|
| `H1` заголовок блока | `Ваши букинги` |
| `H2` строка с датой | `<title>` · `<Дд>, <Д месяца>, <ЧЧ:ММ>` по времени острова из `starts_at` · `.pill` `status_ru` сервера |
| `H3` прежний недельный, согласованный (`starts_at` null) | `<weekday_ru>, <start_local>` · `каждую неделю` |
| `H4` прежний без даты, не согласованный | `<title>` · `Без даты` · `.pill` `status_ru` |
| `H5` у отклонённого | `<amount> ฿ вернулись на счёт` (`.small`) и `decision_note` сервера `.verbatim`, если есть |
| `H8` у согласованного с датой (`status = approved`) | ключ `home.masterBookings.slotFee`: `{amount} ฿ — плата за слот, они остаются клубу.` (`.small`) — решение владельца №46 «б» (фича 4) |
| `H6` своих букингов нет | `Своих букингов нет.` |
| `H7` не загрузились | `Букинги не загрузились` и `Повторить` |

⚠ **`H3` — только для трёх живых недельных мастеров** (ТЗ, «Трое живых
мастеров — ничего не делаем»): их выписанные недели живут, новых нет. Слова
«оплачено до» и «продлить» у них не появляются: продления нет.

## Блоки сверху вниз

| класс | слова | источник |
|---|---|---|
| `.card` | `H1`; строки `H2`–`H5` (`.rows`); `M0` (`.btn`) под списком | `GET /master/requests/mine` → `requests[]` |

Порядок строк — по `starts_at` от ближайшей; `H3`/`H4` — после датированных.

## Данные экрана

`requests[]`: `title, starts_at, start_local, weekday_ru, status, status_ru,
amount, decision_note`. `paid_until`, `paid_till` — null у букингов, НЕ
требуются.

## Состояния

| состояние | что на экране |
|---|---|
| **список** | `H1`, строки, `M0` |
| **пусто** | `H1`, `H6`, `M0` |
| **прошедшие** | букинг с `starts_at` раньше сейчас НЕ показывается — список не копится |
| **не загрузилось** | `H1`, `H7`; `M0` остаётся — подача от списка не зависит |

## Перечитать на входе

Список — на каждый вход на «Клуб» и после `M10`.

## Усечение

`title` строки — одна строка, `.clamp1`.

## Запрещено

| запрещено | прибор |
|---|---|
| прошедший букинг в списке | случай `buking-spisok` |
| строка без `starts_at` как ошибка всего списка | случай `buking-net-starts-at` |
| «Продлить» и «Оплачено до» на «Клубе» | случай `prodlenie-net` |
| «Недель впереди» у букинга с датой | случай `ms-ivent-data` |
| телеграм-id и живое имя в разметке | `tools/ids-clean.cjs`, шаг 7 ворот |

**Признак сборки** (цель числом, единица — ВХОЖДЕНИЯ):
`rg -c 'Ваши букинги' js/`
— **сегодня 0, обязано стать 1** — заголовок `H1`;
`rg -c 'Забукать' js/`
— **сегодня 0**, находка: пройдена при счёте больше нуля — `M0`. Числа нет
НАРОЧНО: слово может стоять и в таблице главной кнопки (`mainFor`), а сколько
мест его держат — свойство сборки, не рецепта.
⚠ «Сегодня» снял прибор сверки по стволу `45b7d59`, не чтение кода (`#975`).

**Проверки:**

- `buking-spisok` — ждущий, согласованный впереди и прежний недельный в списке,
  прошедший — нет;
- `buking-mnogo` — при ждущем `M0` жив;
- `buking-net-starts-at` — строка без даты не роняет список.
