# `guest` · блок «Бизнесы клуба» (шаг 19)

Рецепт БЛОКА внутри чужого экрана по форме `../README.md`: ключ хозяина —
`guest` (вкладка «Услуги»), имя блока — **«Бизнесы клуба»**. Семья — `19`,
состав — `sostav.md` рядом.

⚠ Геометрия и токены сюда НЕ переписаны: уровень класса, радиус и цвет — в
составе, значения уровней — в `../../sostav-shkaly.md`.

⚠ Экран `guest` целиком НЕ переписывается. Шаг 19 трогает ОДНУ группу —
сегодняшнюю «Бар клуба» (`js/11-ekrany-klub.js:74` в живой ветке и `:92` в
демо). Группа «Работа» (`:82`, у работника), группа «Услуги острова» (`:102`,
демо) и карточки «Клуб закрыт для гостей» (`:110`) — не предмет шага.

---

**Зритель:** член клуба. Своего права у блока нет — его даёт вкладка
**«Услуги»** (`TABS`, `js/21-navigaciya.js:227`–`:232`): она есть у `guest`,
`member`, `organizer` и `partner`. Ручка `GET /directions` сторожит только
`caller`, то есть любого с живым `app_access`.

**Вход:** нижняя панель → вкладка **«Услуги»**.

**Выход:** строка бизнеса → `bar` (меню ВЫБРАННОГО бизнеса, рецепт `bar.md`).
Другого выхода у блока нет.

## Блоки сверху вниз

| класс | слова | источник |
|---|---|---|
| `.group` + `.label` | «Бизнесы клуба» | моё |
| `.listitem` → `.grow` → `b.clamp2` — строка на каждый АКТИВНЫЙ бизнес | название бизнеса | `GET /directions` → `title` |
| → `.pill`, у бизнеса с закрытой сменой | «закрыт» | `GET /directions` → `is_open` |
| → `.chev` | стрелка «туда» — как у прочих строк экрана | без изменений |
| `.card quiet` → `.small`, активных нет ни одного | «Пока ни одного бизнеса.» | моё |
| `.card strong` → `h2` · `p` · `.btn` | «Бизнесы не загрузились» · текст отказа сервера · «Повторить» | моё + печать отказа |

**Порядок строк — СЕРВЕРНЫЙ, клиент не сортирует.** Замер: `ORDER BY
d.closed_at IS NOT NULL, d.id` (`directions`, api `f106a1e` — КОММИТ), то есть
активные уже идут первыми. Выбор: не сортировать — из чего: против «закрытые
вниз»; при двух бизнесах переупорядочивание не читается, а второй источник
порядка расходится с сервером молча. Отменяется наблюдением: когда закрытых
станет больше открытых и список начнёт начинаться с закрытых.

## Четыре ветви ТЗ — что видно в каждой

| ветвь ТЗ | что на экране |
|---|---|
| 1 · активных несколько | строка на каждый; нажатие ведёт в меню ИМЕННО ЭТОГО бизнеса |
| 2 · активный один | строка одна; вид и поведение те же, особого случая НЕТ |
| 3 · активен, смена закрыта | строка ПОКАЗАНА, рядом `.pill` «закрыт», строка живая — меню открывается, заказа не даёт (`bar.md`) |
| 4 · не активен | строки НЕТ вовсе; если активных не осталось — вид «пусто» |

## Три решения блока, каждое — ВЫБОР

**Метка только у закрытого.** Что выбрано: `.pill` «закрыт» появляется лишь у
бизнеса с закрытой сменой; у работающего метки нет. Из чего: против
сегодняшней демо-строки, где метка стоит ВСЕГДА и говорит «открыт» или
«закрыт» (`js/11-ekrany-klub.js:97`–`:99`). При N работающих бизнесах N
зелёных меток не сообщают ничего и спорят с названием за ширину строки;
строка без метки читается как «работает». Отменяется наблюдением: если люди
спрашивают «а этот открыт?» про строку без метки.

**`accent` снят.** Что выбрано: строка бизнеса — `.listitem` без `accent`. Из
чего: против сегодняшней `listitem accent` (`:75`, `:93`). `accent` помечает
ОДНО главное действие экрана; N залитых латунью строк не помечают ничего, а
правило «accent, пока бизнес один» и есть тот особый случай, который ТЗ
запрещает (ветвь 2 — «ведёт себя так же»). Отменяется наблюдением: если на
вкладке с одним бизнесом человек не находит дверь — это видно живым проходом,
а не разметкой.

**Подписи у строки нет.** Что выбрано: в строке только название, без `.small`.
Из чего: против сегодняшней подписи «Кофе, чай, авторские · заказ из
приложения» (`:76`, `:96`). Она про БАР: у второго бизнеса она была бы ложью,
а сервер описания не отдаёт ни одним полем (замер — `sostav.md`). Отсутствие
рисуется отсутствием, а не правдоподобной строкой. Отменяется наблюдением:
когда у `GET /directions` появится поле описания — тогда подпись приходит
оттуда, а не из кода.

## Данные блока

`GET /directions` (`directions`, `app/routers/profile.py`) → на члена клуба
отдаёт `id`, `title`, `is_active`, `is_open`. Ключей партнёра и долей члену не
отдаёт (`_is_ops`; `share_*` — только `admin` и куратору своего направления) —
замер по api `f106a1e` (КОММИТ). **Описания бизнеса в ответе нет.**

**Выбор бизнеса держится состоянием, и это ТРЕБОВАНИЕ шага.** Сегодня бизнес
выбирается НАЗВАНИЕМ (`fromDirections`, `js/04-bar.js:21`:
`x.title === 'Бар' && x.is_active`) — единственное место выбора, и его сменяет
`direction_id` выбранной строки. Меню берётся `GET /bar/menu?direction_id=`
этим номером. Экраны `drink`, `barCart`, `barOrder` читают то же состояние —
переименований и своих загрузчиков у них нет.

**Демо-ветка — ОДИН бизнес, и это ВЫБОР.** Что выбрано: демо-набор остаётся
одним бизнесом, у `DATA.bar` (`js/01-osnova.js:101`) появляется только
`title` — название берётся оттуда, а не литералом. Из чего: против демо-набора
из двух бизнесов, которым ветви 1 и 3 стали бы видны владельцу без Telegram.
Второму бизнесу нужно и второе демо-меню, а настоящих позиций второго бизнеса
клуба у нас нет, а выдуманные запрещены словом владельца 21.10.2026 («убери не
существующие услуги»). Отменяется наблюдением: придёт выгрузка позиций второго
бизнеса — демо-набор становится двумя, и ветви 1 и 3 видны в снимке.

## Состояния

| состояние | вид и слова |
|---|---|
| не загрузилось | `.card strong` → `h2` «Бизнесы не загрузились», `p` с текстом отказа сервера, `.btn` **«Повторить»** |
| пусто | `.card quiet` → `.small` «Пока ни одного бизнеса.» |
| отказ по праву | **вида нет, и это замер:** `GET /directions` сторожит только `caller`, а человек без допуска до вкладки не доходит — его держит экран входа (`noAccess`, `js/20-ekrany-sluzhebnye.js`). Любой 4xx/5xx рисуется как «не загрузилось» |

⚠ «Повторить», а не «Попробовать снова» — то же слово, что в семье `bar`
(`../bar/bar.md`): одно действие — одно слово.

⚠ Слово «Пока ни одного бизнеса.» — без хвоста «их открывает клуб»: кто
открывает бизнес, члену клуба не нужно ни для одного действия, а названная
чужая роль читается как подсказка, куда идти.

**Перечитать на входе:** `GET /directions` при каждом входе на вкладку.
Смену открывают и закрывают на баре; старое `is_open` обещало бы заказ,
которого сервер не даст, а старый состав списка показал бы закрытый бизнес
работающим.

**Усечение:** название бизнеса — `.clamp2` (две строки). Носитель обязателен:
предела длины `title` ручка не объявляет, и без носителя длинное название
растянет строку списка. `.clamp1` не годится — два бизнеса с общим началом
названия прочитались бы одинаково.

**Запрещено** — приборы у каждого запрета в `sostav.md`: название литералом;
подпись, которой сервер не отдаёт; неактивный бизнес в списке; погашенная
строка у закрытой смены; метка «открыт».

**Признак сборки** (цель числом, путь обязателен, единица — ВХОЖДЕНИЯ):
`python3 -I tools/v-oblasti.py js/11-ekrany-klub.js guest 'Бар Café XIII'`
— **до сборки 2, обязано стать 0** — название бизнеса больше не литерал;
`python3 -I tools/v-oblasti.py js/11-ekrany-klub.js guest 'Кофе, чай, авторские'`
— **до сборки 2, обязано стать 0** — подпись, обещавшая бар, снята;
`python3 -I tools/v-oblasti.py js/11-ekrany-klub.js guest 'listitem accent'`
— **до сборки 2, обязано стать 0** — строка бизнеса перестала быть главным действием;
`python3 -I tools/v-oblasti.py js/11-ekrany-klub.js guest 'открыт'`
— **до сборки 1, обязано стать 0** — метки у работающего бизнеса нет;
`python3 -I tools/v-oblasti.py js/11-ekrany-klub.js guest 'Бизнесы клуба'`
— **до сборки 0, обязано стать 2** — заголовок группы, по одному в каждой ветке;
`python3 -I tools/v-oblasti.py js/11-ekrany-klub.js guest 'clamp'`
— **до сборки 0, обязано стать 2** — носитель усечения у названия, по одному в каждой ветке;
`python3 -I tools/v-oblasti.py js/11-ekrany-klub.js guest 'Повторить'`
— **до сборки 0, обязано стать 1** — состояние «не загрузилось» получило выход.
⚠ Пустых строк между признаками НЕТ нарочно: прибор сверки берёт блок ДО
пустой строки, и признак за ней стал бы невидим.

⚠ **Область берётся ЭКРАНОМ, а не файлом, и вот цена:** `Бизнесы клуба` по
`js/` даёт **9** вхождений (заголовок экрана `businesses` в `TITLES`, дверь в
него на `manage` и прочее), а в области `guest` — **0**. Признак по файлу или
по клиенту ответил бы на другой вопрос и ответил бы правдоподобно.

⚠ **Две цели, что ждут ДВА вхождения (заголовок группы и носитель усечения),
вязаны к ЧИСЛУ ВЕТОК экрана, а не к предмету.** Сегодня у `guest` ветки две
(живая и демо), и каждая несёт свою группу. Сведут ветки в одну — законная
пара станет одиночкой, и это правка РЕЦЕПТА, а не расхождение сборки. Названо
здесь, чтобы следующий читатель не чинил сборку.

## Чего этот рецепт не несёт

Общий перечень — в `../README.md`. Отдельно по этому блоку:

1. **влезает ли строка** с длинным названием рядом с меткой «закрыт» —
   проверяется отрисовкой, не текстом;
2. **снимка у `guest` нет вовсе** — 0 видов из 31 в таблице `SHOTS`
   (`tools/shots.cjs`; разбор и состояние съёма — в `sostav.md`), поэтому
   приговор `tools/sverka-recepta.py` по классам этого блока скажет
   «сверять нечем», и это НЕ зелёное. Блок судится признаками выше и случаями
   батареи. Предписания «добавить `guest` в `tools/shots.cjs`» здесь нет
   НАРОЧНО: такое предписание по трём экранам семьи 13 уже оказалось ложным
   (решение, `#935`);
3. **три серверные дыры** ТЗ — через экран недостижимы, разбор в `sostav.md`.

## Проверки (случаи батареи, по ветвям ТЗ)

Зона `frontend-upravlenie-ec`: случаи живут в `tools/live.cjs`. Пять — четыре
ветви ТЗ плюс контроль, как и просит ТЗ.

- `biz-dva-aktivnyh` — два активных бизнеса: две строки, вторая ведёт в меню
  ВТОРОГО (ветвь 1). ⚠ Он же второй отрицательный контроль ТЗ: вернуть выбор по
  названию — случай обязан покраснеть на втором бизнесе;
- `biz-odin-aktivnyy` — один активный: одна строка, тот же вид и тот же путь
  (ветвь 2);
- `biz-smena-zakryta` — активный с `is_open=false`: строка показана, метка
  «закрыт», строка ЖИВАЯ, меню открывается (ветвь 3);
- `biz-ne-aktiven-i-pusto` — `is_active=false` у единственного бизнеса: строки

  первый отрицательный контроль ТЗ: снять фильтр `is_active` — случай обязан
  покраснеть;
