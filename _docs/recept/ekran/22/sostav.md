Ингредиенты ОДНОГО предмета шага 22 — экрана `barQueue` (рецепт
`barQueue.md`, имя файла = ключ экрана). Разрешённые шкалы и уровни —
`../../sostav-shkaly.md`. **Числа здесь не повторяются:** состав называет
УРОВЕНЬ, значение живёт в шкале.

БРЕНДБУКУ и по смерженному `bar/barOrder` (тот же предмет — заказ, та же
`.pill` состояния), а не по разметке `liveCard`. Совпадение с разметкой —
ПРЕДПОЛОЖЕНИЕ, его судит опись.

## Что этому предмету ЗАПРЕЩЕНО

| запрещено | прибор |
|---|---|
| строка суммы или цены у работника, в том числе «0 ฿» | случай `rabotnik-bez-summy`: ключа `sum` в ответе нет — и строки нет |
| заказы чужого направления у работника | случай `rabotnik-chuzhoe-napravlenie` |
| вход в `barMoney` / `barDay` у работника | они остаются в `FROZEN` (ТЗ, «чего не несёт») |
| телеграм-id и живое имя члена клуба в разметке | `tools/ids-clean.cjs`, шаг 7 ворот |

| `fromDirections` (`js/04-bar.js:30`) | «своё» направление — и по гранту `worker`; несколько — выбор прежним `BAR_PICK` (дополнение к паспорту, поле 6) |
| ручки очереди и смены состояния | право работника — работа СЕРВЕРА; форма ответа (без `sum`) приедет снимком в карточку `#553` со sha api |

## Чего этот состав НЕ несёт

- слов `barOrder` у члена клуба («Бар принял», «Отправлен на бар»,
  «Назовите его бармену») — они названы в рецепте строкой «что после шага
  врёт», правка вне ТЗ шага 22;
- письма в бота: его текст пишет сервер, клиент в ветви 3 не рисует ничего; подсказки работнику «включите бота» — тоже нет (поправка к ТЗ);
- распределения заказа на одного работника и отказа от него — шаг 39;
- отмены заказа работником — отмена есть возврат денег, не его зона (поправка к ТЗ).
