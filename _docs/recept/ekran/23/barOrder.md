# `barOrder` · дверь к своему заказу, выдача и получение

**Зритель:** член клуба — о СВОЁМ заказе. Экран `barOrder` живой (оттаян,
`WIRED`); шаг 23 даёт к нему ДВЕРЬ, находит выданный заказ и добавляет
подтверждение получения. Работник ставит «выдан» в `barQueue`, как после шага 22.
Нового экрана шаг не строит (ТЗ `Cafe13KPG#554`).

⚠ **Код клиента в этом рецепте не читался** (правило `Cafe13KPG#975`). Всё о
встраивании взято из ПАСПОРТА экрана (комментарий паспорта, `arhitector-b7`;
клиент main `4f0d70f`, api main `41e2e35`) и из снимка формы сервера в той же
карточке. Слова — из ТЗ и смерженного `bar/barOrder`. Где объявленного нет,
стоит слово ПРЕДПОЛОЖЕНИЕ — первый адрес для описи.

| что | откуда (паспорт) |
|---|---|
| экран | `js/16-ekrany-bar.js:190`, живая ветка `:211–227`, демо `:229–` (лента `:233–237`) |
| данные | `GET /bar/orders?direction_id=N` — член клуба получает только свои строки; в строке `state`, `served_at`, `ready_at` (форма — снимок сервера в карточке) |
| загрузка | `pollMine` (`js/05-kassa.js:704`, раз в 8 с, встаёт на `served`/`cancelled` `:734`), `fromOrder` (`:627`) — сегодня берёт только `state` и `created_at` |
| выбор заказа | сегодня: есть `DATA.bar.mine` — по `oid`, иначе первый свой НЕ `served` и НЕ `cancelled` (`:722–724`) → выданный после перезапуска не находится |
| вход | только `go('barOrder')` после покупки (`05-kassa.js:673`, `:685`); двери с экранов нет (паспорт, поле 5) |

## Слова шага 23

| что | слово |
|---|---|
| `R1` дверь на `bar`, заказ есть | `Мой заказ` · `№<номер> · <состояние>` — номер и подпись `OSTATE` от сервера |
| `R2` дверь на `bar`, заказов нет | `Мой заказ` · `заказов нет` |
| `R3` пусто на `barOrder`, ВМЕСТО прежнего «Открытого заказа на сервере нет.» | `За сегодня и вчера заказов нет.` |
| `R4` выдан, не подтверждён | `Выдан в <ЧЧ:ММ>. Заберите и подтвердите получение.` — время из `served_at` |
| `R5` действие | `Подтвердить получение` |
| `R6` получение подтверждено | `Получение подтверждено. Выдан в <ЧЧ:ММ>.` |
| `R7` демо-лента, ВМЕСТО «Выдан — заказ закрыт, строка ушла в книгу клуба» | `Выдан — заказ у вас в руках; подтвердите получение.` |

⚠ **`R3` меняет слово, потому что прежнее после шага ложно:** поиск теперь
находит и выданный заказ, значит «открытого нет» отвечало бы не на тот вопрос.
Пусто — только когда в окне «сегодня и вчера» своих заказов нет ВОВСЕ
(отрицательный контроль 5).

## Четыре состояния

| состояние | где | что на экране |
|---|---|---|
| **дверь к заказу** | `bar` (меню направления), над меню | `.card quiet` → строка `R1`; нажатие → `barOrder`. Дверь стоит ВСЕГДА, пока экран меню открыт |
| **выдан, подтвердите получение** | `barOrder` | прежняя карточка заказа с `.pill` «выдан»; `.small` `R4`; `.btn` `R5` |
| **получение подтверждено** | `barOrder` | та же карточка; `.small` `R6`; кнопки нет |
| **пустая дверь** | `bar` → `barOrder` | на `bar` — `R2`; на `barOrder` — `.card quiet` → `.small` `R3` + прежняя `.btn ghost` «Открыть меню». ⚠ НЕ ошибка и не пустой экран |

**Какой заказ показывает дверь — УМОЛЧАНИЕ АВТОРА:** самый новый свой заказ в
окне «сегодня и вчера», в ЛЮБОМ состоянии, включая выданный и подтверждённый.
`DATA.bar.mine` остаётся подсказкой после покупки, но не условием поиска:
после перезапуска дверь находит тот же заказ по ответу сервера (ветвь 1).

⚠ **Опрос и выдача.** `pollMine` встаёт на `served` — это допустимо, только если
экран успел нарисовать `R4` и `R5`: подтверждение не ждёт опроса, его даёт
нажатие. После `R5` экран перечитывает заказ один раз и рисует `R6`.

⚠ **Отказ подтверждения** (чужой заказ, ещё не выдан) — `.deny` → `.verbatim`,
словами сервера, как есть. Имени ручки и строки отказа в рецепте НЕТ нарочно:
их назовёт сервер снимком формы в карточку (так же, как на шаге 21).

**Запрещено:** обещать, что выдача или получение пишут в книгу клуба или
трогают деньги (умолчание ТЗ: деньги списаны при покупке); показывать кнопку
`R5` до `served`; показывать члену клуба, КТО выдал (`served_by` — ветвь
только сервера); прятать подтверждённый заказ из двери.
