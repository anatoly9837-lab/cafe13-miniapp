# Шаг 23 · Состав: дверь к своему заказу, выдача и получение

Ингредиенты ОДНОГО предмета шага 23 — экрана `barOrder` и двери к нему на
`bar` (рецепт `barOrder.md`). Разрешённые шкалы и уровни —
`../../sostav-shkaly.md`. **Числа здесь не повторяются:** состав называет
УРОВЕНЬ, значение живёт в шкале.

⚠ **Код клиента не читался** (правило `Cafe13KPG#975`): классы названы по
БРЕНДБУКУ и по смерженному `bar/barOrder` (карточка заказа, `.pill`
состояния, `.card quiet` пустого), а не по разметке. Совпадение с разметкой —
ПРЕДПОЛОЖЕНИЕ, его судит опись.

## Что этому предмету ЗАПРЕЩЕНО

| запрещено | прибор |
|---|---|
| слово о книге клуба или деньгах у выдачи и получения | признак `'книгу клуба'` → 0; ТЗ: деньги списаны при покупке |
| кнопка `R5` до `served` | случай `poluchenie-do-vydachi` |
| ошибка или пустой экран у человека без заказов | случай `dver-bez-zakazov` |
| имя выдавшего у члена клуба | ТЗ: `served_by` — ветвь только сервера |
| телеграм-id и живое имя в разметке | `tools/ids-clean.cjs`, шаг 7 ворот |

## Что сборка обязана тронуть, кроме экрана

| место | что встаёт |
|---|---|
| поиск своего заказа (`js/05-kassa.js:722–724`) | самый новый свой в окне, ВКЛЮЧАЯ `served`; `DATA.bar.mine` — подсказка, не условие |
| `fromOrder` | брать `served_at` (сервер отдаёт, клиент выбрасывал — паспорт, поле 4) и признак подтверждения из снимка формы |
| `pollMine` на `served` | опрос может встать, но экран рисует `R4`/`R5`; после `R5` — одно перечитывание |
| меню `bar` | дверь `R1`/`R2` — `data-go="barOrder"` |
| ручка подтверждения | имени в рецепте нет НАРОЧНО — назовёт сервер снимком формы в карточку `#554` со sha api |

## Чего этот состав НЕ несёт

- письма члену клуба о готовности и выдаче — шаг 40;
- живой ленты состояний (кроме правки лжи `R7` в демо);
- имени выдавшего у члена клуба;
- заказов старше суток клуба.
