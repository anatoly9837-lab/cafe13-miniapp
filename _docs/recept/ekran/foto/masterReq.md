# `masterReq` · снимки заявки у того, кто её решает

Рецепт БЛОКА внутри чужого экрана: остальное на `masterReq` («Заявка в
мастера · решение», `js/18-ekrany-mastera.js`) — как сегодня. Вид кадров —
`sostav.md`, таблица «Правка `.album`» (вид события, с `.album-pair`).

**Зритель:** арт-директор, который решает заявку (и админ, которому очередь
видна, — право `mayMasters`). Мастер свою заявку здесь не решает.

**Зачем:** снимки, приложенные к заявке (`masterApply`) и к брони церемонии
(`teaHold` — та же заявка, `occupancy: tea`), при согласии сервер переносит на
карточку ивента (`decide`, api b9ba0e7 `app/routers/master.py:646`) — в
публичное. Без этого блока они уходили туда **никем не просмотренными**: это
причина, по которой загрузка у `masterApply` и `teaHold` закрыта флагом
(`FOTO_ON`, `js/09-afisha.js`, решение координатора 26.11, `Cafe13KPG#1123`).

**Откуда:** `photos[]` {id, url, width, height} в строке `GET /master/requests`
(api b9ba0e7 `ROW_SQL`, `app/routers/master.py:237–249`; форма та же, что у
афиши, — `queries.photos_json_sql`). Разборщик — `fromMasterReq`
(`js/07-mastera.js`), кадры — `fotoFrom`.

## Блоки сверху вниз

`M1` стоит после карточки названия и описания, **перед** отказом сервера и
кнопками решения («Согласовать», «Отказать»): по снимкам решают, поэтому их
видно до кнопки.

| состояние | вид |
|---|---|
| **три снимка** | крупный + два превью в ряд, все видны сразу |
| **два снимка** | два кадра рядом равными половинами |
| **один снимок** | один крупный |
| **снимок грузится / не загрузился** | пустой квадрат `--surface` на своём месте (как у `event.md`) |
| **снимков нет** | блока нет вовсе; экран — как сегодня |
| **сервер без поля `photos`** | как «снимков нет»; заявка показывается |
| **битый кадр в ответе** | кадр отброшен, остальные видны; заявка и очередь не пропадают — снимок не условие заявки (Ф1) |
| **заявка решена** | `M1` остаётся над строкой «Решено …» |

⚠ **Показ от `FOTO_ON` не зависит.** Флаг открывает ЗАГРУЗКУ в форме; есть
`photos` в ответе — блок есть при любом значении флага. Открывает флаги
`masterApply` и `teaHold` координатор, не этот рецепт.

⚠ **Правки снимков здесь нет**: арт-директор снимки не меняет, только видит.

**Признак сборки** (цель числом, путь обязателен, единица — ВХОЖДЕНИЯ):
`python3 -I tools/v-oblasti.py js/18-ekrany-mastera.js masterReq 'teaAlbum\(q\.photos'`
— **сегодня 0 (замер по `b03fdf7`), обязано стать 1** — `M1` на экране решения.

## Проверки

Прибор без браузера — `node tools/foto-zayavka.cjs .` (случаи и мутанты в его шапке).

- `zayavka-tri` — три снимка → крупный и два превью;
- `zayavka-dva` — два снимка → пара равными половинами;
- `zayavka-odin` — один снимок → только крупный;
- `zayavka-net` — снимков нет и поля нет → `.album` в разметке нет, экран один и тот же;
- `zayavka-poryadok` — `.album` после названия и до «Согласовать»;
- `zayavka-chay` — заявка церемонии → снимки видны;
- `zayavka-bityj` — битый кадр → отброшен, заявка и очередь целы;
- `zayavka-flag` — все флаги `FOTO_ON` закрыты и открыт `masterApply` → показ один.

Случай в настоящем DOM — `ms-album` в `tools/live.cjs` (часть 1, блок букинга мастера): заявка с тремя снимками →
альбом ВИДЕН и стоит до «Согласовать»; заявка без снимков → блока нет; флаги `masterApply`/`teaHold` закрыты.
Отрицательный контроль — снятая строка альбома в `js/18` (красное `ms-album-vidno`).

⚠ **Что значит «виден» в этом случае — и чего он НЕ проверяет.** Ловит: альбома нет в разметке; рамка без размера
(`display:none`, `scale(0)`); `img` не загружен или `visibility:hidden`; обрезка предком (`overflow` + `height:0`),
перекрытие другим элементом, `visibility:hidden` у предка — через `elementFromPoint` в центре рамки после прокрутки к
ней; `opacity:0` у `img` или любого предка. **Не ловит:** частичную прозрачность, `filter` (`opacity(0)`,
`brightness(0)`), `clip-path`, заливку поверх кадра псевдоэлементом самой рамки, `mix-blend-mode`, однотонную
картинку от сервера, рамку исчезающе малого размера (2 px засчитаны видимыми: порога нет); проверяется центр
рамки, а не края.
