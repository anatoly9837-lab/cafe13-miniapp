**Пустой блок — по СЧЁТЧИКУ, правило одно для `E1`, `P1` (34) и `E1`, `T1` (36).**
Блок пуст, когда его `count` равен `0`, а не когда сумма `0` или `null`. Тогда
строка счётчика остаётся числом (`Ивентов 0`, `Распределений 0`, `Записей 0`,
`Пополнений 0` — «если нули — значит нули»), а фраза «…не было» встаёт ВМЕСТО
строк сумм. Карточка не прячется. Основание — форма сервера (api `stats.py` на
main `ce232e4`): у `events` при пустом окне суммы `null` (`bookings`,
`collected`, `spent` — api#195), у `payouts` и `topups` сумма `0` (`COALESCE`).
Правило по счётчику даёт одинаковый экран при обеих формах; `null` суммы при
`count > 0` — `нет данных`, как везде.

## Числа — только из ручки (слово владельца 24.11.2026)

Дословно, передано координатором: «Числа нужны. Реальные. Если нули - значит
нули.» Класс — `Cafe13KPG#964` (прототип печатал литеральные 70/30 рядом с
живыми числами). Правило ОБЩЕЕ для всех страниц статистики 33–36 и `eventReport`:

- каждое число на экране — поле ответа ручки как есть; литеральных и
  демонстрационных чисел в разметке экрана НЕТ, в демо — числа фикстуры, а не
  строки кода;
- **ноль** (`0` в ответе) печатается нулём — `.num` с `0`, строка на месте;
- **нет данных** (`null` или поля нет) — ДРУГОЕ состояние и другая разметка:
  вместо `.num` стоит `.small` словом `{экран}.noData` — `нет данных`; нулём
  оно не печатается никогда, иначе отсутствие приедет правдоподобным нулём.
  Ключ — `masterStats.noData` / `eventReport.noData`, слово `нет данных`;
- доли, проценты, суммы не считаются в клиенте из других чисел.

**Признак сверки** (ВХОЖДЕНИЯ; два отдельных приговора):
1. литерал — `rg -n 'class="num">[0-9]' <файл экрана>` в области экрана —
   **обязано быть 0** (число в `.num` приходит переменной, а не цифрой кода);
2. ноль ≠ нет данных — `rg -c '{экран}.noData' js/` — **обязано стать 2**
   (словарь и экран), и случай `*-nol-ne-pusto`: поле `0` → `.num` с `0`;
   поле `null` → `нет данных`, а не `0`.

## Данные экрана

- `GET /stats/master?period=day|week|month&at=YYYY-MM-DD` — есть в стволе api
  (`stats.py:638`, d6ea79b), в бою нет до выкладки; смотрящий = сам (`caller`),
  чужого `member_id` в запросе нет; форма со снимком сервера НЕ сверена;
- `events` — ивенты, где смотрящий автор, только одобренные (№48 «б»: в афише —
  одобренный); отменённые и отклонённые не считаются (ВЫБОР);
- `payouts` — строки распределения на личный счёт смотрящего за окно (доля
  мастера, шаг 7);
- `money.balance` — тот же остаток, что `/me`; `money.withdrawable` — то же
  поле (смысл «можно вывести» зависит от развилки №18 «а» / `#991` «целиком», вопрос у координатора 24.11), что `GET /withdraw/accounts` → `personal.withdrawable` (фича 6, ствол api
  `279a554`); `money.expected` — доля мастера по ВСЕМ его не снятым ивентам с
  деньгами, ещё не распределённым (прошедшим и будущим) — как `money.expected`
  у `/stats/art`, решение api#172; форму назвал сервер (backend-uvedomleniya-b0,
  24.11), sha — по снимку;
- прозы в ответе нет: надписи — ключи клиента;
- плата за слот 100 ฿ — другой канал денег, сюда НЕ входит (вне списка, на
  который спрошено «да»).
