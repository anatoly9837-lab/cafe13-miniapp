# `roleAccount` · счёт роли: остаток и запрос на вывод

**Зритель:** держатель роли со счётом в книге клуба — `art_director` (шаг 27),
`space_manager` (шаг 29), `head` (шаг 30, счёт `club`). Право — видеть остаток
счёта СВОЕЙ роли и просить вывод из него; решает держатель `admin` на
`withdrawQueue` (`../25/withdrawQueue.md`). ОДИН экран на троих, имя счёта
подставляется (ТЗ шагов 26–30, ветвь 4). Экрана сегодня нет ни у кого
(паспорт шага 26, таблица ролей: остаток счёта роли отдаёт только
`/stats/club` под `head`), ключ `roleAccount` свободен.

⚠ **Код клиента не читался** (правило `Cafe13KPG#975`). Встраивание — из
паспорта шагов 26–30 (`arhitector-62`, клиент main `1c3a8c2`, api main
`64955b6`) и его дополнения о поле 5; слова запроса — те же, что у мастера
(`../25/withdraw.md`) и партнёра (`../26/bizMoney.md`): механика одна.

| откуда / куда | как |
|---|---|
| вход | «Клуб» (`home`) → группа «Ваши роли» → строка `R1` под плашками, по строке на КАЖДЫЙ счёт роли человека; строка несёт счёт |

(дополнение к паспорту, поле 5). «Управление» есть у `art_director` и `head`,
у `space_manager` его нет; «Ваши роли» есть у всех троих. Отменяется, если
`space_manager` получит «Управление».

другое. Поэтому в списке запросов стоит, КТО просил: на общем счёте чужой
запрос — не ошибка экрана. `R10` — только у своего ждущего.

## Данные экрана

- остаток счёта роли — после вычитания выплат (ТЗ, контроль 7);
- запросы этого счёта: сумма, состояние, КТО просил, время, причина отказа;
- подача: сумма и счёт (`art_director` / `space_manager` / `club`);
- отмена своего ждущего запроса;
- для `R1` на «Клубе» — какие счета ролей есть у человека (из его ролей).

Имена ручек — снимком формы сервера в карточку `#557`, не здесь.
