# `topup` · пополнить счёт из кошелька — любому вошедшему

**Рецепт ЧАСТИЧНЫЙ:** кто видит `topup` и что на нём живое после фичи 8.
Экран и путь «Онлайн» есть сегодня (кадр `screens/33-topup.png`): «Онлайн —
перевод по реквизитам клуба, с чеком», «Касса» и «USDT — пока только баты»
серые, «История пополнений».

**Решение координатора** (`Cafe13KPG#1009`, три решения по фиче 8, пункт 1):
пополнение с чеком — путь из кошелька, **доступный любому**, рядом с
«Внести на счёт»; канал внесения денег не может быть привилегией выгнанных.
⚠ Код клиента не читался (`#975`).

## Сервер этот путь уже держит — правки не нужно

`POST /topup/request` `{amount, receipt_mime, receipt_base64}` (api,
`app/routers/topup.py`, `Cafe13KPG#503`): привратник — `caller`, то есть любой
с допуском, а допуск после двери есть у любого вошедшего. Решает держатель
роли `topups`; согласие кладёт сумму на счёт строкой `topup/transfer`.

Слова владельца 29.10.2026, которые этот путь держит (`topup.py:9–21`), —
рецепт их НЕ меняет:
- **«От 500 бат»** — порог заявки, 422 словами сервера ниже порога;
- **«оставим только пополнение батами… USDT пока просто сделай не активной»** —
  строка USDT серая, точка;
- отказ — «Мы не получили деньги» (причина по умолчанию).

⚠ Порог 500 ฿ — это ДРУГОЙ путь, чем просьба с чеком api #180 («минимума
нет»): там сумму называл выгнанный, здесь — вошедший. Если координатор хочет
«без минимума» и здесь — это слово владельца 29.10 и правка сервера, не
рецепта.

## Что меняет фича 8

| место | было | после фичи 8 |
|---|---|---|
| вход «Внести себе на счёт» на «Клубе» и экран `topup` | по праву `canTopup` | у ЛЮБОГО вошедшего, новичок включительно |
| строка «Онлайн» | живая | живая, как сегодня |
| строка «Касса» | серая | серая до разморозки кассы (`tillTopup.md`, условие — `arrival_id`) |
| строка «USDT» | серая | серая — слово владельца 29.10.2026 |

⚠ **Видит ли `topup` новичок сегодня, рецепт не знает:** право `canTopup`
у вида «гость без ролей» прибор видимости снимает ложью
(`screens/vidimost.json`, вывод по коду клиента), но то же у «куратора с
живым членством» — значит право не про членство, и сверить его должна рука
клиента. Требование одно: вход и экран — у любого вошедшего.

⚠ **Порог 500 ฿ держится** (слово владельца; вопрос ему — №50, ответ правит одну строку): у кого меньше — путь один,
наличные на кассе (`tillTopup.md`, после `arrival_id`).

## Признак сборки

Случай `topup-novichok`: вид «гость без ролей» достигает `topup` с «Клуба»,
строка «Онлайн» живая. Снять правку — новичок `topup` не достигает.

## Запрещено

| запрещено | прибор |
|---|---|
| `topup` только у членов или ролей | случай `topup-novichok` |
| строка USDT живая | случай `topup-novichok` |
| свой порог суммы в клиенте вместо 422 сервера | случай `topup-porog` |
