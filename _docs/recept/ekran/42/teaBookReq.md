# `teaBookReq` · решение арт-директора по брони церемонии (№98)

Как `teaReq.md` (поле слов, две кнопки, «уже решена», отказ сервера). Доводы —
`teaBookReq-dovody.md`. Очередь — `teaBooks.md`.

**Редакция 27.11.2026 — по серверу в бою `a04c4dd`, цепочка №98:** решается
только бронь, с которой мастер уже согласился (`master_ok`). Рецепт пишет
клиентская рука ДО кода, первым коммитом PR.

**Зритель:** арт-директор (`mayMasters()`). Он может только согласовать или
отказать. Править бронь, менять время или мастера он НЕ может.

## Вход / Выход

| откуда / куда | как |
|---|---|
| вход | `teaBooks` → `V1` (только бронь в `master_ok`) |
| `U5` | согласовать → назад на `teaBooks` с `U7` |
| `U6` | отказать (слова — по желанию) → назад на `teaBooks` с `U8` |
| `U10` | `К очереди` → `teaBooks` |
| назад | `teaBooks` |

## Слова

| что | слово |
|---|---|
| заголовок | имя гостя `.clamp1` |
| `U1` суть | `.rows`: `Мастер` — `master_name`; `Когда` — `teaWhen` (вид `B2` у `teaBook`); `Оплачено` — `<price> ฿` (`.num`) |
| `U11` состояние | `.st wait` со словом сервера `status_ru` печатью (`.verbatim`) — `мастер согласился, ждёт арт-директора` |
| `U2` поле | `.field`, `<label>` `Слова гостю`; `textarea`, предел 500; `.small` `Увидит, если откажете. Можно не писать.` |
| `U3` о согласии | `.small` над кнопками: `Согласие займёт это время в календаре клуба.` |
| `U4` о возврате | `.small` над кнопками: `При отказе гостю вернутся все <price> ฿, доля клуба тоже.` |
| `U5` кнопка | `.btn`: `Согласовать` |
| `U6` кнопка | `.btn ghost`: `Отказать и вернуть <price> ฿` |
| `U7` удача согласия | `flash`: `Бронь согласована.` |
| `U8` удача отказа | `flash`: `Вы отказали. <price> ฿ вернулись гостю на счёт.` |
| `U9` отказ сервера | `.deny` → `.verbatim`: слово отказа как есть |
| `U10` решать нельзя | `.card quiet` и `.btn quiet` `К очереди`; слово — по ПЕРЕЧИТАННОМУ состоянию брони: `pending` → `Мастер ещё не согласился. Решать можно после его согласия.`; `approved` или `rejected` → `Эту бронь уже решили.` |
| `U12` возврат под `U10` | у решённой отказом при `refunded = true`: `.small` `<price> ฿ вернулись гостю на счёт.` |
| отправка | обе кнопки гаснут, на нажатой `Отправляем…` (`tea.sending`) |

⚠ **`U2`–`U6` рисуются только при истинном `teaMayDecide(бронь)`, и это ВЫЗОВ
предиката, а не условие, разнесённое по разметке** — тот же предикат, что
режет группы на `teaBooks`. Истинен он при `status === 'master_ok'`: только
эту бронь сервер решает. Бронь в `pending` кнопок НЕ показывает — иначе
человек нажмёт и получит 409 «мастер ещё не согласился». Вместо кнопок —
`U10`. Попасть сюда с ждущей мастера можно через устаревшую очередь или по
409: экран судит по последнему ответу сервера, а не по тому, откуда пришёл.

⚠ **Отказ — это возврат, и это видно до нажатия:** сумма стоит в `U4` и на
самой кнопке `U6` (№86 «а»). После нажатия `U8` называет сумму ещё раз (№98:
«Если отказывает ар Direct деньги также возвращаются»). Сумму в `U8` даёт
ОТВЕТ решения: `price`, а строка ставится по `refunded = true`. Пришёл
`rejected` без `refunded` — вместо `U8` пишется `.small` со словом сервера
`status_ru`: экран не обещает возврат, которого сервер не сделал.

⚠ **Согласовать бывает нельзя:** время церемонии прошло, или за время
ожидания клуб заняли. Тогда сервер отказывает согласию и сам говорит
«…согласовать нельзя — откажите, деньги вернутся гостю» — это `U9`
`.verbatim`. Поле `U2` сохранено, `U6` жив: решение остаётся за человеком.

⚠ **Любой 409 решения — перечитать очередь** (как клиент `teaReq`). По одному
ответу причины не развести: «мастер ещё не согласился», «бронь уже решена»,
«свою бронь решает другой арт-директор», «время прошло» и «клуб занят»
приходят 409 без кода. После перечитывания:
- бронь в `master_ok` → `U9` словами сервера, кнопки живые;
- в `pending` или решена → `U10` по перечитанному состоянию.

⚠ **Своя бронь** (арт-директор — гость или мастер этой брони): сервер отказывает
409, `U9`. Экран кнопок заранее не прячет: Telegram id гостя и мастера сервер
наружу не отдаёт, а судить «своя» по имени — ложь.

⚠ **Под чужим лицом (act-as) решения нет:** сервер отказывает
(`_not_acting`) — `U9` словами сервера.

## Данные экрана

| что | ручка | поля |
|---|---|---|
| бронь | из очереди `GET /tea/bookings` (`teaBooks`) по `id` | строка `_row(queue=True)` |
| решение | `POST /tea/bookings/{id}/decide` (`tea_bookings.decide`, бой `a04c4dd`), тело `{decision: 'approved' \| 'rejected', note}` — `master.Decision`, `note` ≤ 500 | ответ — строка `_row(queue=True)`: `status`, `status_ru`, `refunded`, `price` |

## Что меняется после нажатия

| когда | что видно |
|---|---|
| **сразу** | `U5` и `U6` гаснут, на нажатой `Отправляем…`; второе нажатие запроса не шлёт |
| **ответ 200, согласие** | переход на `teaBooks`, `U7`; бронь из ответа — в `V2` со словом `согласовано` |
| **ответ 200, отказ** | переход на `teaBooks`, `U8` с суммой из ответа; бронь — в `V2` со словом сервера и строкой `V8` |
| **409** | очередь перечитывается; дальше — по перечитанному (выше) |
| **иной отказ** | `U9` словами сервера, `U2` с набранным сохранено, кнопки живые |

## Состояния

| состояние | что на экране |
|---|---|
| **ждёт арт-директора** (`master_ok`) | `U1`, `U11`, `U2`–`U6` |
| **решаем** | обе кнопки погашены до ответа |
| **ждёт мастера** (`pending`) | `U1`, `U11` со словом сервера, `U10` — кнопок нет |
| **уже решена** | `U1`, `U11`, `U10`; у отказа с возвратом — `U12` |
| **согласовать нельзя** (прошло, клуб занят) | `U9`, `U2` сохранено, `U6` жив |
| **отказ сервера** (прочее) | `U9`, `U2` сохранено |
| **брони нет в перечитанной очереди** | назад на `teaBooks` без `U10`: состояния брони экран не знает и не выдумывает |
