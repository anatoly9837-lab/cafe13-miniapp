# `teaBookReq` · доводы

Признака сборки здесь нет, прибор сверки этот файл не судит. Рецепт — `teaBookReq.md`.

## Отказ — возврат (№86 «а»)

Ответ владельца 26.11: «Вернуть гостю всё» — отказ по оплаченной брони
возвращает ВСЮ цену, 100 ฿ клуба тоже (журнал `Cafe13KPG/_docs/decisions.md`,
раздел «26.11.2026, 15:30 ICT»). Координатор 26.11: на экране решения должно
быть видно, что отказ — это возврат, а не просто «нет». Поэтому сумма стоит
на кнопке, а не только в подсказке.

## Согласие держит время

Сервер: ждущая бронь время не держит (иначе любая подача захватывала бы
слот), держит согласие. Строка `U3` говорит арт-директору, что его «да»
меняет календарь для всех.

## Почему «согласовать нельзя» не прячет кнопку заранее

Клуб могут занять в любую секунду ожидания. Экран не гадает: судит сервер
(№61), его слово показывается как есть и само подсказывает выход — отказ с
возвратом.

## Чего нет и почему

- согласие и отказ мастера — на своём экране `teaToMe` (№98, сервер `a04c4dd`);
  здесь видно только их итог: бронь приходит в `master_ok`;
- деление денег согласованной брони — вопрос владельцу №93;
- отмена после согласия — на сервере её нет, правило не написано.

## Почему кнопок нет у брони, ждущей мастера (редакция 27.11.2026)

№98: арт-директор решает ПОСЛЕ мастера, и сервер `a04c4dd` отвечает 409 на
решение по `pending`. Кнопка, которая заведомо получит отказ, — ложь экрана.
Кнопки рисует один предикат `teaMayDecide`, общий с очередью, чтобы очередь и
экран решения не разошлись в том, что можно решать.

## Почему сумма возврата — из ответа

Возврат делает сервер (`_refund`, встречная строка на всю цену). Экран
говорит о нём, только когда ответ это подтвердил (`refunded = true`), и
называет цену из того же ответа. Слова «деньги вернутся» до нажатия (`U4`,
`U6`) — обещание по цене брони, слово после (`U8`) — по факту.
