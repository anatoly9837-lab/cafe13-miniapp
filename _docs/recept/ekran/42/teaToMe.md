# `teaToMe` · брони ко мне — согласие и отказ мастера (№98)

Рецепт пишет клиентская рука ДО кода, первым коммитом PR: дизайнер не поднят,
прецедент — шаг 44 (наряд координатора 27.11.2026). Это запись ЗАМЫСЛА: код
собирается по нему, а не он по коду.

**Зачем экран.** Слово владельца №98 (26.11): «На согласование арт директору
заявка попадает после того Как её подтвердил мастер». Сервер в бою (`a04c4dd`,
`/health` 27.11 20:05Z) держит порядок кодом: `tea_bookings.decide` решает
ТОЛЬКО бронь в `master_ok`, а ждущую мастера отдаёт 409. Поставить `master_ok`
можно только `tea_bookings.accept` (`POST /tea/bookings/{id}/accept`). Вызовов
`accept` в клиенте на стволе `b1f1d7b` — 0. Без этого экрана бронь, созданная
гостем, встанет в `pending` с деньгами гостя на удержании, и решить её не
сможет никто.

Этим экраном закрывается развилка Р3 (`razvilki.md`): мастер подтверждает
**в приложении**, ручкой сервера. Письма в бота с кнопкой нет: в
`tea_bookings.accept` его нет («Письма арт-директору здесь нет — это отдельная
работа», докстринг).

**Зритель:** мастер, у которого есть согласованная карточка чайного мастера.
Права ему не нужно: сервер отдаёт по `tea_bookings.bookings_to_me` брони, где
`master_member_id` равен Telegram id вызывающего, то есть **только брони к
нему**. Роль не проверяется ни сервером, ни клиентом. Роль одна — `master`
(`sostav.md`), отдельной роли «чайный мастер» нет.

## Вход / Выход

| откуда / куда | как |
|---|---|
| вход | `home`, блок «Чайный мастер» (`home.md`), состояния **согласована** и **правка на согласовании**: `T0` `.btn quiet` `Брони ко мне` рядом с `H3` |
| назад | `home` |
| после согласия | экран остаётся на месте, бронь остаётся в списке (`T6`) |

⚠ **Вход есть только у согласованной карточки.** Без живой карточки гость
этого мастера не забронирует (`tea_bookings._create` берёт `LIVE_SQL`), и
список был бы пуст по построению.

⚠ **Дверь `teaToMe` в `WIRED` этим PR НЕ ставится.** Броней в бою нет, пока
закрыта дверь `teaBook` (`TEA_URL.book = null`, `teaBook` вне `WIRED`).
Открывать `teaToMe` нужно **вместе** с `teaBook`, одним решением координатора.
Открыть `teaBook` без `teaToMe` значит повторить нынешнюю дыру: брони
создаются, а согласиться на них нечем. Пока экран закрыт, в живом режиме
`T0` не рисуется (`closed('teaToMe')`), как у `K5`.

## Блоки сверху вниз

| № | класс | слова | источник |
|---|---|---|---|
| `T1` | `.small` | `Гости забронировали у вас церемонию. Согласитесь — бронь уйдёт арт-директору, он решает последним.` | клиент |
| `T2` | `.card` на бронь | `<b>` день и время (`teaWhen`, вид `B11` у `teaBook`); `.row`: `.st <вид>` + слово состояния | время — `starts_at` + `duration_min` |
| `T2a` | `.small .clamp1` в `T2` | имя гостя | `guest_name` |
| `T2b` | `.num` в `T2` | цена брони, `<price> ฿` | `price` |
| `T3` | `.st` в `T2` | **слово сервера** `status_ru` печатью (`.verbatim` у слова); вид — `TEA_BOOK_ST`: `pending`, `master_ok` → `wait`, `approved` → `ok`, `rejected` → `no` | `status_ru`, `STATUS_RU` в `tea_bookings` |
| `T4` | `.btn` в `T2` | `Согласиться` | клиент |
| `T5` | `.deny` под `T4` | отказ сервера печатью (`.verbatim`) | `detail` ответа |
| `T7` | `.btn ghost` в `T2`, рядом с `T4` | `Отказаться` | клиент |
| `T8` | `.field` в `T2`, после `T7` | `<label>` `Причина — её увидит гость. Можно не писать.`; `textarea`, предел 500 | клиент; предел — `MasterRefusal.note`, `max_length=500` |
| `T9` | `.btn ghost` под `T8` | `Отказать и вернуть деньги` | клиент |
| `T9a` | `.btn quiet` рядом с `T9` | `Не отказывать` | клиент |
| `T10` | `.small` в `T2` у отказанной с возвратом | `<price> ฿ вернулись гостю на счёт.` | `refunded` и `price` |

⚠ **Слова состояния — сервера, своих клиент не заводит.** В бою `STATUS_RU`:
`ждёт решения` · `мастер согласился, ждёт арт-директора` · `согласовано` ·
`отклонено, деньги возвращены на счёт` (замер по `a04c4dd`). Клиент их не
копирует: печатает `status_ru` из ответа. Сменит сервер слово — экран сменит
его сам.

⚠ **Отказ — та же половина решения, что согласие** (№98, дословно: «Если
мастер отказывает то пользователю возвращаются деньги»). Без него ждущая бронь
стоит: арт-директор `pending` не решает (409), а согласиться мастер может не
захотеть.

⚠ **Отказ в два шага:** `T7` только раскрывает `T8`–`T9a`, запроса не шлёт.
Деньги уходят по `T9`. Довод — необратимость: после отказа бронь `rejected`,
и вернуть её нечем (`tea_bookings.refuse`: только из `pending`).

⚠ **`T4` и `T7` рисуются только при истинном `teaMayAccept(бронь)`, и это ВЫЗОВ
предиката, а не условие, разнесённое по разметке.** Предикат истинен, когда
выполнены ОБА условия:
- состояние брони `pending` (сервер принимает согласие только из него, иначе 409);
- `master_id` брони равен номеру своей карточки (`teaMyId()`, номер первой
  подачи, `api#228`), а не Telegram id.

Сервер отдаёт чужому 403 (`tea_bookings._own_booking`), но кнопка, которая
заведомо получит отказ, — ложь экрана. Чужую бронь `bookings_to_me` не отдаёт,
так что второе условие сторожит другое: ответ, где чужая бронь всё-таки
оказалась, и разбор, который перепутал номер. Номер своей карточки не пришёл
(`TEA.mine` не загрузился) — кнопки нет ни у одной брони, а список виден.

## Что меняется после нажатия

| когда | что видно |
|---|---|
| **сразу** | `T4` гаснет (`disabled`) со словом `Отправляем…` (`tea.sending`). Гаснет только у ЭТОЙ брони, остальные строки без изменений. Второе нажатие запроса не шлёт |
| **ответ 200** | строка брони заменяется строкой **из ответа** (`accept` возвращает `_row(queue=True)`): `T3` → `мастер согласился, ждёт арт-директора` печатью сервера, `T4` исчезает (состояние уже не `pending`). Над списком — `T6` |
| **ответ 409 / 403 / иной** | `T5` словами сервера под этой бронью; кнопка снова живая; список перечитывается (409 обычно значит, что бронь уже не ждёт мастера) |

`T6` — `flash`: `Вы согласились. Бронь ушла арт-директору — решает он.`

| отказ — когда | что видно |
|---|---|
| **`T7`** | под бронью `T8` и `T9`/`T9a`; набранное в `T8` живёт до `T9a` или ухода с экрана |
| **`T9` сразу** | `T9` гаснет со словом `Отправляем…`; гаснут и `T4`, `T7` этой брони |
| **ответ 200** | строка — из ответа (`refuse` возвращает `_row(queue=True)`): `T3` → `отклонено, деньги возвращены на счёт` печатью сервера, вид `no`; **`T10` с суммой**; кнопок нет. Над списком `T11` |
| **отказ сервера** | `T5` словами сервера, поле `T8` с набранным остаётся, список перечитывается |

`T11` — `flash`: `Вы отказались. Деньги вернулись гостю на счёт.`

⚠ **`T10` — обязательная строка, не украшение:** без неё мастер видит «отклонено»
и не знает, что стало с деньгами гостя. Показывается при `refunded = true`;
сумма — `price` брони (возврат ВСЕЙ цены, №86 «а», `tea_bookings._refund`).

⚠ **После согласия бронь остаётся в списке.** Пропавшая строка читалась бы
как «бронь пропала» или «отказали». Остаётся она в `master_ok`, с вида `wait`
и словом сервера про арт-директора. **Список не пустеет и при перечитывании:**
`master_ok` обязан стоять в `TEA_BOOK_ST` (`#501`), иначе незнакомое состояние
отбросит весь ответ (`every(Boolean)`).

## Данные экрана

| что | ручка | поля |
|---|---|---|
| список | `GET /tea/bookings/to-me` (`tea_bookings.bookings_to_me`, бой `a04c4dd`) | `id`, `master_id`, `guest_name`, `starts_at`, `duration_min`, `price` строкой, `status`, `status_ru` |
| согласие | `POST /tea/bookings/{id}/accept` (`tea_bookings.accept`), тела нет | ответ — та же форма строки |
| отказ | `POST /tea/bookings/{id}/refuse` (`tea_bookings.refuse`), тело `{note}` — `MasterRefusal`, необязательно, ≤ 500 | ответ — та же форма строки, `refunded`, `refused_by_master` |
| свой номер мастера | `GET /tea/card/mine` (уже грузится для `home`) | `card.master_id` / `live.master_id` |

Порядок — сервера: ждущие мастера сверху (`ORDER BY (b.status = 'pending')
DESC, b.starts_at`). Клиент не пересортировывает.

## Состояния

| состояние | вид |
|---|---|
| грузится | `.small` `Загружаем…` (`tea.card.loading`) |
| пусто | `.card quiet`: `<b>Броней пока нет</b>`; `.small` `Здесь появятся брони гостей на вашу церемонию.` |
| не загрузилось | `teaRetry`: `Брони не загрузились` и `Повторить` |
| незнакомое состояние в ответе | как «не загрузилось»: список не выдумывается (вид `T5` у `teaBook`) |

## Перечитать на входе

Список — на каждый вход и после любого ответа на `T4`, кроме 200 (тогда строка
уже из ответа). Своя карточка (`TEA.mine`) — если не загружена.

## Усечение

Имя гостя — `.clamp1`. Слово сервера `T3` не усекается: в нём состояние.

## Чего экран НЕ несёт

- отмена после согласия: на сервере её нет (`refuse` только из `pending`);
- очередь арт-директора (`teaBooks`, `teaBookReq`) — свои рецепты, кода нет;
- письмо мастеру о брони — его шлёт сервер (`notify.tea_booking_to_master`).

## Запрещено

| запрещено | прибор |
|---|---|
| `T4` или `T7` у брони чужого мастера | случай `tea-ko-mne-chuzhoj` (`tools/chay-ko-mne.cjs`) |
| отказ одним нажатием, без `T9` | случай `tea-ko-mne-otkaz-mastera` (`T7` запроса не шлёт) |
| отказанная без строки о возврате | случай `tea-ko-mne-vozvrat` |
| `T4` у брони не в `pending` | случай `tea-ko-mne-soglasie` (после 200 кнопки нет) |
| свои слова состояния вместо `status_ru` | случай `tea-ko-mne-slovo-servera` |
| пустой список при брони в `master_ok` | случай `tea-ko-mne-master-ok` |

**Признак сборки** (цель числом, путь обязателен, единица — ВХОЖДЕНИЯ):
`rg -c 'teaToMe' js/`
— **сегодня 0 (замер по `b1f1d7b`), обязано стать ≥ 3**: экран, `back`, вход `T0`.

**Проверки** (`tools/chay-ko-mne.cjs`, без браузера, ответы в форме `_row`):

- `tea-ko-mne-soglasie` — своя ждущая: `T4` есть → нажатие шлёт `POST /tea/bookings/<id>/accept` → по ответу `master_ok` слово `мастер согласился, ждёт арт-директора`, `T4` нет, `T6` про арт-директора;
- `tea-ko-mne-chuzhoj` — ждущая другого мастера: строка есть, `T4` нет;
- `tea-ko-mne-master-ok` — `master_ok` рядом с ждущей: обе в списке;
- `tea-ko-mne-slovo-servera` — `status_ru` сервера печатается как есть;
- `tea-ko-mne-otkaz` — 409 на согласие: `T5` словами сервера, список перечитан;
- `tea-ko-mne-otkaz-mastera` — своя ждущая: `T7` раскрывает поле, запроса нет → `T9` шлёт `POST /tea/bookings/<id>/refuse` с `{note}` набранного → по ответу `rejected` слово сервера, кнопок нет, `T11`;
- `tea-ko-mne-vozvrat` — отказанная с `refunded = true`: `T10` `<price> ฿ вернулись гостю на счёт.`

Мутанты: снять условие «чей мастер» в `teaMayAccept` → краснеет
`tea-ko-mne-chuzhoj` и только он; снять условие `pending` → краснеют
`tea-ko-mne-soglasie` (кнопка после 200) и `tea-ko-mne-master-ok`; убрать
`master_ok` из `TEA_BOOK_ST` → краснеет `tea-ko-mne-master-ok` (список
пустеет), а с ним `tea-ko-mne-soglasie`: ответ `accept` приходит в `master_ok` и
тоже не разбирается; снять строку `T10` → краснеет `tea-ko-mne-vozvrat`.
