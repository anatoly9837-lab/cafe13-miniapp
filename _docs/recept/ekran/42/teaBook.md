# `teaBook` · бронь чайного мастера гостем

**Зритель:** вошедший через Telegram. Право — забронировать мастера на дату и
время со СВОЕГО счёта. Требует ли бронь членства, решает сервер шага 42:
отказ придёт его словами в `B9`.

**Что такое бронь — слово владельца 25.11.2026, цитата 5:** «Отчаянный мастер
[чайный мастер — распознавание речи] создает чайную церемонию, либо его
бронируют на чайную церемонию, что одно и тоже. […] либо какой-то гость
специально под себя бронирую чайного мастера также создавая чайную церемонию в
пространстве.» Значит бронь — это ЦЕРЕМОНИЯ, созданная гостем. Сущность та же,
что у церемонии от мастера (ТЗ: «в данных это ОДНА сущность»).

**Два подтверждения, оба нужны** (ТЗ, раздел «№60 закрыт»):

1. мастер подтверждает бронь — ответ №57 «а», дословно: «При бронировании в
   бота уходит уведомление о том что его забронировали. Если мастер отклоняет
   бронь, то все деньги возвращаются пользователю.»;
2. арт-директор согласует церемонию — №60, дословно: «арт директор согласуют
   все чайные церемонии, также как и ивенты».

⚠ **Порядок этих двух владелец НЕ называл.** Экран не выдумывает «сначала
мастер, потом директор». Он показывает два независимых признака (`B11`), и
каждый говорит только о себе.

| что | слово |
|---|---|

| `B1` под заголовком | `.small`: `<имя мастера> · церемония <price> ฿` (`.num` у суммы) |
| `B2` время | `.card`: подпись `Время`; пока не выбрано — `.btn quiet` `Выбрать время в календаре` → `calendar` в режиме «выбрать»; выбрано — `Ср, 2 декабря · 19:07–20:37` и `.btn quiet mini` `Изменить` |
| `B2b` окно церемонии | конец = начало + длительность из карточки мастера (№62 «а»); гость выбирает в календаре только НАЧАЛО |
| `B6` цена | `Спишется · <price> ฿` |
| `B7` недостача | `Не хватает <N> ฿` строкой у кнопки; кнопка погашена |
| `B8` кнопка | `Забронировать`; погашена, пока время не выбрано |
| `B9` отказ сервера | `.deny` → `.verbatim`: `detail` сервера как есть |
| `B10` удача, на `teaMaster` | `Бронь отправлена. Мастеру ушло письмо в бота.` |
| `B11` своя бронь у этого мастера | `.card quiet`: дата и время; две строки — `Мастер` с `.st` `ждёт` / `подтвердил` / `отказал` и `Арт-директор` с `.st` `ждёт` / `согласовал` / `отказал` |
| `B12` отказ мастера | под `B11`: `<сумма> ฿ вернулись на счёт.` |

**Какое время занято и почему — говорит календарь** (`../43/calendar.md`,
режим «выбрать»): ивент, полные места (№61 «а», ёмкость — число сервера),
другая церемония ЭТОГО мастера (цитата 11), прошлое. Цитата 10: «Для того
чтобы забронировать церемонию на определённое время тебе нужно выбрать это
время в календаре». Своей занятости дня у `teaBook` больше нет.

⚠ **Календарь не единственный страж.** Сервер отказывает брони, чьё окно
занято, даже если время пришло мимо календаря; отказ — `B9` словами сервера
(граница — `../43/calendar.md`).

⚠ **Слоты без имён.** Календарь говорит «<k> из <ёмкость>», а не «стол 2». Слово
владельца: «Называть эти слоты не будем». Гость стол не выбирает, сервер
ставит церемонию в любой свободный.

⚠ **Чужие церемонии без названий и без имён мастеров**, только сколько
занято. ВЫБОР дизайнера: брони гостей — частное дело, а гостю для выбора
времени нужно одно число.

⚠ **Любая минута, без шага 30.** Слово владельца об ивентах: «ивенты могут
начинаться в любое время то есть в любой час и в любую минуту». ТЗ п. 7
распространяет его на букинг мастера. Для церемонии это ВЫВОД ТЗ: владелец
говорил об ивентах.

## №62 — длительность: ответ владельца «а»

Длительность ставит мастер в своей карточке (`teaApply.md` `A4b`), гость
выбирает только начало. Окно церемонии `[начало, начало + длительность]`
сервер кладёт на ивенты, места и церемонии мастера. Ответ №61 «а»: мест три
(число сервера).

| `.card` | `B2` | выбранное в `calendar` время |
| `.card` | `B6` (`.num`), `B7`, `B8` (`.btn`) | цена из карточки, остаток счёта |
| `.deny` | `B9` | ответ запроса брони |

## Данные экрана

- цена — из карточки мастера, перечитанной на входе (`teaMaster.md`);
- занятость дня читает `calendar`, не этот экран;
- запрос брони: номер мастера, дата, время начала (окно сервер строит по длительности карточки, №62 «а»). Места НЕТ (цитаты 7, 8,
  `sostav.md`), стола НЕТ (слоты без имён);
- остаток счёта — тем же источником, что шапка.
