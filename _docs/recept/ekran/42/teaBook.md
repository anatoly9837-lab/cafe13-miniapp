# `teaBook` · бронь чайного мастера гостем

**Зритель:** вошедший через Telegram. Право — забронировать мастера на дату и
время со СВОЕГО счёта. Требует ли бронь членства, решает сервер шага 42:
отказ придёт его словами в `B9`.

**Что такое бронь — слово владельца 25.11.2026, цитата 5:** «Отчаянный мастер
[чайный мастер — распознавание речи] создает чайную церемонию, либо его
бронируют на чайную церемонию, что одно и тоже. […] либо какой-то гость
специально под себя бронирую чайного мастера также создавая чайную церемонию в
пространстве.» Значит бронь — это ЦЕРЕМОНИЯ, созданная гостем. Сущность та же,
что у церемонии от мастера (ТЗ: «в данных это ОДНА сущность»).

**Два подтверждения, оба нужны** (ТЗ, раздел «№60 закрыт»):

1. мастер подтверждает бронь — ответ №57 «а», дословно: «При бронировании в
   бота уходит уведомление о том что его забронировали. Если мастер отклоняет
   бронь, то все деньги возвращаются пользователю.»;
2. арт-директор согласует церемонию — №60, дословно: «арт директор согласуют
   все чайные церемонии, также как и ивенты».

⚠ **Порядок этих двух владелец НЕ называл.** Экран не выдумывает «сначала
мастер, потом директор». Он показывает два независимых признака (`B11`), и
каждый говорит только о себе.

| `B3` занятость дня | заголовок `В этот день`; строки занятости (ниже); пусто — `В этот день свободно` |
| `B4` не помещается | `.small`: `В это время мест для церемонии нет — выберите другое.` |
| `B5` прошедшее время | `Это время уже прошло — выберите другое.` |
| `B5b` дата раньше сегодня | `Выберите дату — сегодня или позже.` |
| `B6` цена | `Спишется · <price> ฿` |
| `B7` недостача | `Не хватает <N> ฿` строкой у кнопки; кнопка погашена |
| `B8` кнопка | `Забронировать` |
| `B9` отказ сервера | `.deny` → `.verbatim`: `detail` сервера как есть |
| `B10` удача, на `teaMaster` | `Бронь отправлена. Мастеру ушло письмо в бота.` |
| `B11` своя бронь у этого мастера | `.card quiet`: дата и время; две строки — `Мастер` с `.st` `ждёт` / `подтвердил` / `отказал` и `Арт-директор` с `.st` `ждёт` / `согласовал` / `отказал` |
| `B12` отказ мастера | под `B11`: `<сумма> ฿ вернулись на счёт.` |

**Строки занятости `B3`** — что видно гостю в выбранный день:

| что занимает | строка |
|---|---|
| ивент афиши | `ЧЧ:ММ–ЧЧ:ММ · ивент — церемоний нет` |
| церемонии | `ЧЧ:ММ–ЧЧ:ММ · занято <k> из 3 мест для церемоний` |

⚠ **«Ивент — церемоний нет» — СЛОВО ВЛАДЕЛЬЦА, а не вывод:** цитата 7
(действует): «во время ивента чайные церемонии проходить не могут»; раньше то
же — цитата 5. Перекрёстную блокировку делает сервер (ТЗ п. 1). Экран только
показывает её, иначе гость увидит свободное время, которого нет.

⚠ **«3» — число сервера, а не константа клиента.** Слово владельца «на
сегодня» сделать три слота, значит число изменится. В разметке `3` нет, число
приходит ответом (поле ёмкости).
⚠ **Три слота — допущение координатора, ответа владельца нет (№61).**
Довод координатора: цитата 5 говорит «сделаем три слота», цитата 7 убрала
только привязку к пространству, а о числе молчит, значит отменять счёт нечем.
Если ответ «предела нет», снимаются строка церемоний из `B3` и `B4`, а ивент
остаётся единственным, что закрывает время. Другие блоки не меняются.

⚠ **Слоты без имён.** Строка говорит «<k> из 3», а не «стол 2». Слово
владельца: «Называть эти слоты не будем». Гость стол не выбирает, сервер
ставит церемонию в любой свободный.

⚠ **Чужие церемонии без названий и без имён мастеров**, только сколько
занято. ВЫБОР дизайнера: брони гостей — частное дело, а гостю для выбора
времени нужно одно число.

⚠ **Любая минута, без шага 30.** Слово владельца об ивентах: «ивенты могут
начинаться в любое время то есть в любой час и в любую минуту». ТЗ п. 7
распространяет его на букинг мастера. Для церемонии это ВЫВОД ТЗ: владелец
говорил об ивентах.

## №62 — длительность церемонии при брони гостем (вопрос владельцу)

Цитата 1 называет цену «за проведение чайной церемонии», то есть за одну
церемонию, а не за час. Сколько длится церемония, владелец не сказал. Без
длительности сервер не посчитает пересечение с ивентом и тремя слотами.

- **а)** длительность ставит мастер в своей карточке (одна на его церемонию),
  гость выбирает только дату и время. Цена та же. Цена: поле в `teaApply`.
- **б)** длительность выбирает гость при брони, цена от неё не зависит.
  Цена: гость может занять стол на сутки за одну цену.
- **в)** длительность согласуют вживую. При брони занимается окно по
  умолчанию, арт-директор правит при согласовании. Цена: число по умолчанию
  называет владелец.

**Рецепт построен на «а» — допущение координатора, ответа владельца нет.**
Довод: цена названа «за проведение», то есть за услугу целиком; гость выбирает
дату и время. Рекомендация дизайнера та же.

**Из чего считается пересечение — ОКНО церемонии:** `[время гостя, время
гостя + длительность]`. Сервер кладёт окно на ивенты (любой ивент закрывает,
цитата 7) и на церемонии (не больше ёмкости, №61). Без длительности окна нет,
и пересечение не считается вовсе.

**Ответ владельца меняет ОДИН блок — `B2b`, и ничего больше:**

| ответ | `B2b` | что ещё |
|---|---|---|
| а (допущение) | строка `Церемония <Ч:ММ> · до ЧЧ:ММ`, длительность из карточки | поле длительности в `teaApply` (`A4b`) |
| б | поле `Длительность` у гостя, тело брони несёт её | `A4b` снимается |
| в | строка `Окно по умолчанию <Ч:ММ>. Арт-директор уточнит.` | `A4b` снимается |

`B3`, `B4`, `B6`–`B12` от ответа не зависят: окно у них уже посчитано.

## Данные экрана

- цена — из карточки мастера, перечитанной на входе (`teaMaster.md`);
- занятость ОДНОГО дня: ивенты и церемонии. Ответ о другой дате не
  принимается (тот же довод, что `../master/masterApply.md`, `M3`);
- запрос брони: номер мастера, дата, время (окно сервер строит по длительности карточки, допущение №62). Места НЕТ (цитаты 7, 8,
  `sostav.md`), стола НЕТ (слоты без имён);
- остаток счёта — тем же источником, что шапка.
