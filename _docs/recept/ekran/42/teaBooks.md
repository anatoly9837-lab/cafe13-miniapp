# `teaBooks` · очередь броней церемоний у арт-директора (№98)

Как `teaReqs.md` (форма очереди: ждущие сверху, решённые ниже). Доводы —
`teaBooks-dovody.md`.

**Редакция 27.11.2026 — по серверу в бою `a04c4dd`, цепочка №98.** Прежняя
редакция писалась по `a6d4d4c`, когда мастер в цепочке не стоял, и ставила
под решение ВСЕ ждущие брони. Сейчас сервер решает только бронь, с которой
согласился мастер (`master_ok`), а по ждущей мастера (`pending`) отвечает
409 «мастер ещё не согласился» (`tea_bookings.decide`). Рецепт пишет
клиентская рука ДО кода, первым коммитом PR (прецедент — `teaToMe.md`). Это
запись замысла: код собирается по ней.

**Цепочка владельца (№98):** гость бронирует → мастер соглашается или
отказывает (`teaToMe`) → **арт-директор решает здесь**. Этот экран —
последнее звено. Пока его нет, бронь доходит до `master_ok` и стоит, а деньги
гостя всё это время на удержании.

**Зритель:** арт-директор (`mayMasters()`: роль `art_director` или админ). Он
открывает бронь и решает её на `teaBookReq`. Сервер даёт читать очередь и
главе клуба (`READS`), но двери у главы нет (`masters` закрыт без права
арт-директора), поэтому экран ему не рисуется.

## Вход / Выход

| откуда / куда | как |
|---|---|
| вход | `masters` → `S2` |
| `V1` | строка брони, ждущей арт-директора → `teaBookReq` |
| `V6`, `V3` | строки без перехода: решать в них нечего |
| назад | `masters` |

## Слова

| что | слово |
|---|---|
| заголовок | `Брони церемоний` |
| `V0` группа | `Ждут вашего решения` |
| `V1` строка брони в `master_ok` | имя гостя `.clamp1`; `.small` — `мастер <master_name> · <teaWhen>`; справа `.st wait` со словом сервера `status_ru` печатью (`.verbatim`); шеврон |
| `V7` группа | `Ждут мастера` |
| `V6` строка брони в `pending` | как `V1`, но **без шеврона и без перехода**; `.st wait` со словом сервера; `.small` второй строкой: `Решать можно после согласия мастера.` |
| `V2` группа | `Решённые` |
| `V3` строка решённой | имя гостя; `.small` — мастер и время; `.st ok` или `.st no` со словом сервера печатью |
| `V8` возврат под решённой | `.small` у отказанной при `refunded = true`: `<price> ฿ вернулись гостю на счёт.` |
| `V4` пусто | `.card quiet`: `<b>Броней нет</b>`; `.small` `Здесь появятся брони, которые гости делают у чайных мастеров.` |
| `V5` не загрузилось | `teaRetry`: `Брони не загрузились` и `Попробовать снова` |
| грузится | `.small` `Загружаем…` (`tea.card.loading`) |

⚠ **Слова состояния — сервера, своих клиент не заводит** (как `teaToMe`). В бою
`STATUS_RU`: `ждёт решения` · `мастер согласился, ждёт арт-директора` ·
`согласовано` · `отклонено, деньги возвращены на счёт` (замер по `a04c4dd`).
Вид `.st` берётся по `TEA_BOOK_ST` (`pending`, `master_ok` → `wait`, `approved`
→ `ok`, `rejected` → `no`), слово — `status_ru` из ответа.

⚠ **Группа строки — ПО ПРЕДИКАТУ, а не по разметке.** В `V0` бронь попадает,
только когда `teaMayDecide(бронь)` истинен. Это ВЫЗОВ одного предиката, его
же зовёт `teaBookReq` перед кнопками. Истинен он ровно при `status ===
'master_ok'`: только эту бронь сервер решает. Бронь в `pending` идёт в `V7`
без перехода. Покажи её под решением — человек нажмёт и получит 409.

⚠ **`V8` — обязательная строка, не украшение** (№98: «Если отказывает ар
Direct деньги также возвращаются»). Ставится по `refunded = true` из ответа, а
не по слову `rejected`: возврат виден, только когда сервер его сделал. Сумма —
`price` брони: возвращается ВСЯ цена (№86 «а», `tea_bookings._refund`).
Отказ мастера (`refused_by_master`) возвращает так же, и строка та же.

⚠ **Порядок — сервера, клиент не пересортировывает:** `master_ok` сверху,
за ним `pending`, внутри по времени церемонии (`ORDER BY (b.status =
'master_ok') DESC, (b.status = 'pending') DESC, b.starts_at, b.id`). Группы
режут готовый порядок и сохраняют его.

⚠ **Аватарки нет** — у гостя нет карточки с кадром; строка без `.avatar`.

⚠ **Незнакомое состояние в ответе** (не из `TEA_BOOK_ST`) — как «не
загрузилось» (`V5`): список не выдумывается. Тот же разбор, что у `teaBook` и
`teaToMe` (`every(Boolean)`).

## Данные экрана

| что | ручка | поля |
|---|---|---|
| очередь | `GET /tea/bookings` (`tea_bookings.queue`, бой `a04c4dd`) | `{bookings, pending, master_ok}`; строка — `_row(queue=True)`: `id`, `master_id`, `master_name`, `guest_name`, `starts_at`, `duration_min`, `price` строкой, `status`, `status_ru`, `note`, `refunded`, `refused_by_master` |
| счёт для `S2` | тот же ответ | `master_ok` — брони, ждущие арт-директора |

## Перечитать на входе

Очередь — на каждый вход, после решения на `teaBookReq` и после любого 409
решения.

## Чего экран НЕ несёт

- кнопки решения в строке: решение только на `teaBookReq`;
- отмену согласованной брони: на сервере её нет (отказ согласованной — 409);
- деление денег согласованной брони: вопрос владельцу №93;
- церемонию, поданную мастером (№60): развилка Р2, открыта.
