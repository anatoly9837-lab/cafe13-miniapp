# `bizMoney` · блок «Вывод» — запрос партнёра на вывод денег бизнеса

**Зритель:** партнёр бизнеса — ВЛАДЕНИЕ (`directions.partner_id`), роли нет
(паспорт шага 26, поле 3). Право — просить вывод из кошелька СВОЕГО бизнеса;
решает держатель `admin` на `withdrawQueue` (рецепт `../25/withdrawQueue.md`).

Экран есть — `bizMoney` (рецепт шага 20, `../20/bizMoney.md`), остаток партнёр
уже видит. Шаг 26 добавляет в него ОДИН блок: запрос и состояния запросов
(ТЗ шагов 26–30, ветвь 3). Нового экрана нет.

⚠ **Код клиента не читался** (правило `Cafe13KPG#975`). Встраивание — из
паспорта (`arhitector-62`, клиент main `1c3a8c2`, api main `64955b6`), слова —
по рецепту шага 25 (`../25/withdraw.md`): один предмет, одни слова.

## Блоки сверху вниз

Блок встаёт ПОД шапкой с остатком (рецепт шага 20, блок 1) и над выбором
бизнеса нет — он следует выбранному:

| класс | слова | источник |
|---|---|---|
| `.card` | `B2` (`.small`), поле суммы `.field`, `B4` (`.btn`) | остаток — шапка экрана, `GET /partner/directions` |
| `.deny` → `.verbatim` | отказ подачи | ответ сервера, как есть |
| `.rows` | запросы ВЫБРАННОГО бизнеса: сумма, `.pill`, время; у ждущего `B10` (`.btn ghost`) | список запросов — ручка сервера, с `direction_id` |

## Данные экрана

- остаток — прежний `wallet` из `GET /partner/directions` (паспорт, поле 4);
- запросы бизнеса: сумма, состояние, время подачи и решения, причина отказа;
- подача: сумма и `direction_id` выбранного бизнеса — без него у партнёра с
  двумя бизнесами не узнать кошелёк (паспорт, «чего сервер не даёт»);
- отмена своего ждущего запроса.

Имена ручек — снимком формы сервера в карточку `#557`, не здесь.

## Состояния

| состояние | что в блоке |
|---|---|
| **доли не назначены** (`wallet` = `null`) | блока НЕТ: выводить нечего, и слово остатка шага 20 уже это говорит |
| **запросов нет** | `B2`, форма, «Запросов на вывод ещё не было.» |
| **ждёт решения** | строка с «ждёт решения» и `B10` |
| **решён** | «одобрен — списано со счёта» или «отказан»; остаток в шапке перечитан той же `GET /partner/directions` (паспорт, поле 6) |
| **отказ подачи** (больше остатка; чужой бизнес — 403) | `.deny` → `.verbatim` словами сервера; сумма сохраняется |
| **не загрузилось** | «Запросы не загрузились.» и `Повторить`; формы нет — без списка партнёр подал бы второй запрос вслепую |
| **два бизнеса** | блок следует выбору (`BW.biz`): запросы и подача — выбранного; смена бизнеса перечитывает список |

## Перечитать на входе

Остаток (`GET /partner/directions`) и запросы выбранного бизнеса — на входе,
после `B4`/`B10` и при смене бизнеса.

## Усечение

Причина отказа — `.small`, растёт, не режется.

**Запрещено:** сравнивать сумму с остатком в клиенте; подставлять остаток в
поле; подавать запрос без `direction_id` выбранного бизнеса; обещать способ и срок выплаты; телеграм-id и живое имя
в разметке.

**Признак сборки** (цель числом, единица — ВХОЖДЕНИЯ):
Файл — `js/17-ekrany-upravlenie.js`, область `bizMoney` (паспорт, поле 1).
`python3 -I tools/v-oblasti.py js/17-ekrany-upravlenie.js bizMoney 'Попросить вывод'`
— **обязано стать 1** — слово `B4`; сегодня 0 (вывода в клиенте нет, паспорт, поле 7);
`python3 -I tools/v-oblasti.py js/17-ekrany-upravlenie.js bizMoney 'долю за закрытые месяцы'`
— **обязано стать 1** — слово `B2`;
`python3 -I tools/v-oblasti.py js/17-ekrany-upravlenie.js bizMoney 'переведём'`
— **обязано стать 0** — способа выплаты блок не обещает.

**Проверки** — ветвь 3 ТЗ и контроли 1, 5, 7 (контроли 2–4 — общие с
шагом 25, их несёт очередь `withdrawQueue`):
