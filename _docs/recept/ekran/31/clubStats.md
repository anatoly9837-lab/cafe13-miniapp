## Данные экрана

- `GET /stats/club?period=day|week|month&at=YYYY-MM-DD` — одна ручка на всю
  страницу;
- `club{member,master,event,partner,total,balance}` — уже есть;
  `unknown_joins` на экран не идёт (ТЗ: «что на экране» его не называет);
- НОВЫЕ поля — по снимку формы в `#688` (api `61db38e`):
  `memberships{new,live,live_at}`, `events{count,bookings,collected}`,
  `till{arrivals}`, `business{closed,current}`;
- `business.closed.note` и `business.current.note` НЕ печатаются — тот же
  выбор, что ниже: слово держит рецепт (`B1`, `B3`);
- **дата закрытия текущего месяца бизнеса — `business.current.closes_on`**
  (ISO «ГГГГ-ММ-ДД» по поясу клуба; ответ `backend-uvedomleniya-4e` 24.11, снимок
  формы со sha — в `#688`): клиент её не считает, только пишет словами;
- `business.current = null` — окно не задевает текущий месяц, `B3` нет;
- `business.current.note` сервера НЕ печатается — ВЫБОР: из двух источников
  одной строки (`note` / слова `B3` с датой) взят второй, чтобы слово держал
  признак рецепта, а не ответ. Отменяется, если сервер начнёт менять смысл
  `note` по состоянию (тогда — `.verbatim`). Даты в `note` нет вовсе.
