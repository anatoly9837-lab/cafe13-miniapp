# `barCart` · заказ

Рецепт ОДНОГО экрана по форме `../README.md`. Семья — `bar`, состав семьи —
`sostav.md` рядом. Экран ОТТАИВАЕМЫЙ: собран и закрыт заморозкой.

⚠ **Единственный экран витрины вместе с `barRecipe`, у которого НЕТ отдельной
демо-ветки**: тело одно на оба режима. Значит здесь — и только здесь в семье —
**снимок годится доказательством**, и шаг 7 судит картинку, а не одну разметку.
У `bar`, `drink` и `barOrder` снимок показывает демо-ветку.

⚠ Геометрия и токены сюда НЕ переписаны: уровень класса, радиус и цвет — в
составе, значения уровней — в `../../sostav-shkaly.md`.

---

**Зритель:** член клуба, собравший заказ. Своего права у экрана нет — вход
даёт непустая корзина.

**Вход:** «Оформить» на `bar`, «Оформить заказ» на `drink`. **Выход:**
`barOrder` (заказ создан), `topup` («Пополнить счёт»), `bar` («Открыть меню» в
пустом состоянии).

| класс | слова | источник |
|---|---|---|
| `.group` + `.label` | «Состав» | моё |
| `.card` на позицию + шаговик `stepper` (`js/21-navigaciya.js:126`) | название · «N × цена = сумма ฿» · «−» и «+» | `CART`, меню |
| `.group` + `.label` | «Куда подать» | моё |
| `.seg` — три кнопки | «за стойку» · «к столу» · «с собой» | моё; выбранная несёт `aria-pressed` |
| `.group` + `.label` | «Оплата» | моё |
| `.rows` одной строкой | «Со счёта в клубе» · «на счёте N ฿» | остаток члена |
| `.note` | «Спишем со счёта сразу, когда заказ создан, — не при выдаче. Наличные бар не принимает. Пополнить можно у хостес. Отменить заказ может только бар — тогда деньги вернутся на счёт.» | моё; механика — `place_order` |
| `.deny` (`role="alert"`) → текст | печать отказа сервера дословно | `place_order` |
| `.btn quiet` под отказом | «Пополнить счёт» — только у отказа о нехватке | см. долг ниже |
| `.sum` → `.big num` | «Итого» · сумма ฿ | `CART` |
| `.btn dup-main` | «Купить», при отправке — «Отправляем…» и погашена | моё |

**Данные экрана:** `POST /bar/orders` ← `direction_id`, позиции, `place`
(`where`), `pay_method`. Ответ → номер заказа, состояние, сумма. Остаток — из
профиля члена; цены — из уже загруженного меню.

⚠ **Способ оплаты один, и это решение сервера, а не экрана:** `place_order`
отказывает всему, кроме `account`, словами «на баре платят со счёта в клубе;
пополнить можно у хостес». Колонка `pay_method` на сервере осталась под
наличные «когда у бара появится касса» — то есть выбора нет СЕГОДНЯ, и показ
второго способа обещал бы то, чего нет.

**Состояния:**

| состояние | вид и слова |
|---|---|
| пусто | `.card quiet` → `.small` «Заказ пуст.» + `.btn ghost` «Открыть меню» |
| отправка | `.btn dup-main` «Отправляем…», погашена (`disabled`) |
| отказ | `.deny` словами СЕРВЕРА, пять адресов — все в `place_order` |
| не загрузилось | своего нет: меню и остаток приходят раньше, их состояния на `bar` |

**Пять отказов «Купить» — по имени функции, не по номеру строки** (`place_order`,
api `origin/main`): 409 «бар закрыт: смена не открыта, заказ принять некому»;
400 «нет таких позиций в этом меню: …»; 409 «позиция снята с меню: …»; 409 «на
баре платят со счёта в клубе; пополнить можно у хостес»; 409 «на счёте N, не
хватает M». Слова не копируются в разметку — печатается полученное.

**Перечитать на входе:** остаток и смену. Цена позиции уже в корзине, а
остаток и `BAR.open` решают, уйдёт ли заказ; старое число обещало бы покупку,
которой сервер не даст.

**Усечение:** название позиции в строке состава — `.clamp1`, одна строка с
хвостом; текст отказа сервера — без обрезки, он содержит число и причину.

**Запрещено** (прибор у каждого):

| запрет | прибор |
|---|---|
| наличные как способ оплаты | построением: второго способа на экране нет. `rg -c 'наличн' js/16-ekrany-bar.js` — сегодня 2, оба законны (примечание `:155`, расход бара `:450`); ожидание: число НЕ РАСТЁТ |
| НОВОЕ ветвление по тексту отказа | `rg -c 'test\(DENY\)' js/` — сегодня 1 (`:162`), ожидание: число НЕ РАСТЁТ. ⚠ Скобки экранованы: без экранирования это группа регулярного выражения и не находит ничего |
| своя арифметика скидки или доли | `rg -c 'meter' js/16-ekrany-bar.js` — сегодня 2 (полосы бара); ожидание: число НЕ РАСТЁТ |
| обещать отмену заказа членом клуба | `rg -c 'Отменить заказ' js/16-ekrany-bar.js` — сегодня 1, и это примечание «Отменить заказ может только бар»; ожидание: число НЕ РАСТЁТ |

**Долг с названной ценой — разбор ПРОЗЫ отказа.** Кнопка «Пополнить счёт»
показывается, только если текст отказа начинается словами «на счёте»
(`js/16-ekrany-bar.js:162`). Это единственное такое ветвление в клиенте
(счётом, а не на слово). Переформулирует сервер свой 409 — кнопка исчезнет
молча, и человек останется с отказом без выхода. Карточка — `Cafe13KPG#914`.

⚠ **Адрес серверной половины: `place_order`**, строка с
`f"на счёте {balance}, не хватает {total - balance}"` — f-строка, 409. НЕ
`bar.py:474`: там другая ручка (состояние карточки товара), и `str(e).strip()`
в ней — НАРОЧНЫЙ проброс текста триггера с названной причиной («пересказ своими
словами завёл бы вторую копию»). Лечить надо то место, которое клиент читает.

**Признак сборки** (цель числом):
`python3 -I tools/v-oblasti.py js/16-ekrany-bar.js barCart 'clamp1'` —
**сегодня 0, обязано стать 1** (усечение названия позиции в строке состава).

Область признака — ЭКРАН, а не файл: семья живёт в одном `js/16-ekrany-bar.js`,
и счёт `rg -c` по файлу считает заодно работу соседей по семье (условие
прибора — `../uslovia-pribora.md`). Замер в области: `tools/v-oblasti.py`.

⚠ **Прежняя редакция считала `clamp1` по файлу и на сданной витрине дала 2 при
цели 1 — ложное КРАСНОЕ на верной сборке.** Вторая находка — ЗАКОННАЯ строка
`barOrder` («Что заказано», тот же носитель усечения). Расхождение нашёл
сборщик и назвал верно: разошёлся рецепт, а не сборка. Это единственный из
четырёх промахов области, который кто-то заметил, — ложное красное возвращают в
тот же день, ложное зелёное молчит.

⚠ Признак на «Заказ пуст» НЕ ГОДИТСЯ, и это стоит рядом как пример: `rg -c
'Заказ пуст' js/16-ekrany-bar.js` даёт сегодня 1 — это и есть ЭТОТ экран, то
есть признак на существование истинен до сборки. Пример стоит ПОСЛЕ годного
признака нарочно: в одном абзаце перед ним он сбивал машинный разбор, который
берёт первую команду.

## Чего этот рецепт не несёт

Общий перечень — в `../README.md`. Отдельно по этому экрану:

1. **Влезает ли строка состава** с длинным названием и шаговиком в одну
   строку — отрисовкой, не текстом;
2. **Что покажет сервер на пятый отказ сразу после первого** (две причины
   одновременно) — у `place_order` порядок проверок свой, и рецепт его не
   назначает;
3. **Серверная половина разбора прозы** — `Cafe13KPG#914`, не правка клиента.
