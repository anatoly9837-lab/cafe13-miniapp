# `drink` · позиция меню

Рецепт ОДНОГО экрана по форме `../README.md`. Семья — `bar`, состав семьи —
`sostav.md` рядом. Экран ОТТАИВАЕМЫЙ: собран и закрыт заморозкой.

⚠ Геометрия и токены сюда НЕ переписаны: уровень класса, радиус и цвет — в
составе, значения уровней — в `../../sostav-shkaly.md`.

---

**Зритель:** член клуба. Строку «Рецепт» видит только тот, кого пускает сервер
— `mayRecipe()` (`js/09-afisha.js:927`, снято с `_needs_bar_side`): админ, а
бар и куратор — на СВОЁМ направлении. Гостю сервер рецепт не отдаёт вовсе.

**Вход:** строка меню на `bar`. **Выход:** `barCart` («Оформить заказ»),
`topup` («Не хватает N ฿»), `barRecipe` (строка «Рецепт»), `bar` («Открыть
меню» в состояниях).

| класс | слова | источник |
|---|---|---|
| плитка — помощник `tile` (`js/21-navigaciya.js:114`) | буква названия на тоне позиции, либо `.tile empty` со словами «фото не показано» · «без фото» · «фото готовится» | `shot`, `photo`, `tone` |
| `.group` → `h1` | название позиции | `title` |
| `.group` → `p` | описание позиции | `full` или `about` |
| `.rows` | «Цена» · сумма ฿ | `price` |
| `.rows` | «Готовится» · «N мин» — строка есть, только если `mins` назван | `mins` |
| `.rows` | «На счёте» · сумма ฿ | остаток члена |
| кнопка покупки — помощник `buyBtn` (`js/21-navigaciya.js:137`) | «Купить за N ฿» · «Бар закрыт» · «Не хватает N ฿» · «Отправляем…» | `price`, остаток, `BAR.open`, `BUSY` |
| `.card` + шаговик `stepper`, если позиция в заказе | «В заказе» · «N × цена = сумма ฿» · «−» и «+» | `CART` |
| `.btn ghost` | «Оформить заказ» (если в заказе) / «В заказ» (если нет) | моё |
| `.listitem` → `.grow`, только при `mayRecipe()` | «Рецепт» · «Как готовить · สูตร» · стрелка `.chev` | моё |

⚠ **ВЫБОР, а не замер:** описание печатается `p`, то есть ПРИГЛУШЁННЫМ
(`styles.css:207`). Выбрано из двух: приглушённое описание или тушь. Решение о
покупке держат название и цена, описание поясняет — поэтому приглушённое. Если
окажется, что люди читают описание как главное (а это видно только на людях, не
на разметке), выбор переигрывается в пользу туши.

**Данные экрана:** позиция ищется в уже загруженном меню —
`findDrink(id)` по `DATA.bar.menu` (`js/08-kartochki.js:279`). СВОЕЙ ручки у
экрана нет: меню приходит на `bar` через `GET /bar/menu`, смена — через
`GET /directions`.

**Состояния.** ⚠ Сейчас в сборке их ТРИ, СЛИТЫХ В ОДНО: ветка `!d`
(`js/16-ekrany-bar.js:64`) печатает «Такой позиции в меню нет.» и когда меню
ещё грузится, и когда оно не загрузилось, и когда позиции правда нет. Человек
с непришедшим меню читает, что напитка не существует. Рецепт их разводит:

| состояние | признак | вид и слова |
|---|---|---|
| меню грузится | `MENU_STATE` пусто или `loading` | `.card quiet` → `.small` «Загружаем меню…» |
| меню не загрузилось | `MENU_STATE` — текст отказа | `.card strong` → `h2` «Меню не загрузилось», `p` с текстом сервера, `.btn` **«Повторить»** |
| позиции нет | меню загружено (`MENU_STATE === 'ok'`), а `findDrink` пуст | `.card quiet` → `.small` «Такой позиции в меню нет.» + `.btn ghost` «Открыть меню» |

⚠ **Своего загрузчика у экрана нет и не нужно** — он ЧИТАЕТ `MENU_STATE`
бара. Третье состояние остаётся «позиции нет» только тогда, когда меню
действительно пришло: это единственный случай, когда слово правдиво.

**Перечитать на входе:** остаток и смену. Цена позиции приходит с меню, а
остаток и `BAR.open` решают, какое из четырёх слов покажет кнопка покупки.

**Усечение:** название (`h1`) — две строки, `.clamp2`; описание — без обрезки,
оно и есть содержание экрана; «Как готовить · สูตร» — своё слово, не усекается.

**Запрещено** (прибор у каждого):

| запрет | прибор |
|---|---|
| писать «без фото», когда фотография ЕСТЬ | запрет ПОСТРОЕНИЕМ: в `tile` первым спрашивается `d.photo` и печатается «фото не показано». Случай батареи: позиция с `photo` и `shot ≠ ready` → «фото не показано», а не «без фото» |
| «Купить» при закрытой смене | построением: `buyBtn` отдаёт погашенную «Бар закрыт» |
| строка «Рецепт» зрителю без права | `rg -c 'mayRecipe' js/16-ekrany-bar.js` — сегодня 2 (`drink` и `barRecipe`); ожидание: число НЕ УБЫВАЕТ |
| доля, `%`, число доли клуба | `rg -c 'meter' js/16-ekrany-bar.js` — сегодня 2 (полосы бара); ожидание: число НЕ РАСТЁТ |
| обещать «Фотография: снято, не отправлено» члену клуба | строка «Фотография» есть ТОЛЬКО в демо-ветке; `rg -c 'Фотография' js/16-ekrany-bar.js` — сегодня 1, и это демо |

**Признак сборки** (цель числом): `rg -c 'Меню не загрузилось' js/16-ekrany-bar.js` — **сегодня 1 (только на `bar`), обязано стать 2.** Признак целит в ТРЕБОВАНИЕ
рецепта: разведённое состояние «меню не загрузилось» на этом экране. Признак на
существование ключа `drink` был бы истинен в день написания рецепта.

## Чего этот рецепт не несёт

Общий перечень — в `../README.md`. Отдельно по этому экрану:

1. **Решение по демо-ветке** — за владельцем: в демо есть строка «Фотография»
   и кнопка зовётся «Добавить в заказ» вместо «В заказ». Пока решения нет,
   запреты выше названы с ожиданием, а не с приговором;
2. **Снимок этого экрана показывает ДЕМО** (у `drink` своя демо-ветка),
   поэтому расхождение рецепта и сборки судится по разметке и коду;
3. **Влезает ли длинное название** в две строки рядом с плиткой — отрисовкой,
   не текстом.
