# `barOrder` · мой заказ

Рецепт ОДНОГО экрана по форме `../README.md`. Семья — `bar`, состав семьи —
`sostav.md` рядом. Экран ОТТАИВАЕМЫЙ: собран и закрыт заморозкой.

⚠ У экрана СВОЯ демо-ветка, поэтому снимок показывает демо, а не живой экран:
шаг 7 здесь судит разметку и код. Снимок годен только у `barCart` и
`barRecipe`.

⚠ Геометрия и токены сюда НЕ переписаны: уровень класса, радиус и цвет — в
составе, значения уровней — в `../../sostav-shkaly.md`.

---

**Зритель:** член клуба, сделавший заказ. Своего права у экрана нет: сервер
отдаёт только СВОЙ открытый заказ.

**Вход:** после «Купить» на `barCart`. ⚠ Второго входа у экрана НЕТ: пока
заказ открыт, вернуться к нему можно только через меню (`bar` → ...), и это
названо дырой в «чего рецепт не несёт», а не описано как путь.
**Выход:** `bar` («Вернуться в меню»).

| класс | слова | источник |
|---|---|---|
| `.num-wrap` → `.label` | «номер заказа» | моё |
| `.num-wrap` → `.num-big` | номер | ответ сервера; кегль даёт РОДИТЕЛЬ `.num-wrap` (38 px) |
| `.num-wrap` → `.small` | «Назовите его бармену» | моё |
| `.rows` | «Статус заказа» · `.pill` со словом состояния | `OSTATE` (`js/01-osnova.js:194`): «новый» · «готовится» · «готов» · «выдан» · «отменён» |
| `.rows` | «Куда» · «за стойку» либо «к столу» либо «с собой» | `where` |
| `.rows` | «Оплата» · «Со счёта · уже списано» | `pay` |
| `.rows` | «Сумма» · сумма ฿ — строки НЕТ, если сумма не пришла | `sum` |
| `.group` → `h2` | «Что заказано» | моё |
| `.group` → `.rows` | название · «N шт» | `items` |
| `.btn ghost` | «Вернуться в меню» | моё |

⚠ **`sum === null` значит «сервер не сказал», а не «ноль»**, и строка «Сумма»
тогда не печатается вовсе. Поставить там `0 ฿` значило бы соврать числом.

**Данные экрана:** `GET /bar/orders?direction_id=<бар>` → свой открытый заказ:
номер, состояние, `where`, `pay`, `sum`, `items`. Направление берётся по
НАЗВАНИЮ из `GET /directions`.

**Состояния:**

| состояние | вид и слова |
|---|---|
| заказа нет | `.card quiet` → `.small` «Открытого заказа на сервере нет.» + `.btn ghost` «Открыть меню» |
| отменён | `.card strong` → `h2` номер, `.small` «Заказ отменён.» и, если платили со счёта, « Деньги вернулись на счёт: на счёте N ฿.» + `.pill` «отменён» + «Открыть меню» |
| не загрузилось | `.card quiet` с текстом отказа сервера **и `.btn` «Повторить»** — см. требование ниже |
| пусто | своего нет: пустой заказ — это «заказа нет» выше |

⚠ **«Не загрузилось» сегодня БЕЗ ВЫХОДА.** Текст отказа печатается
`.card quiet`, а кнопки повтора нет (замер по `js/16-ekrany-bar.js`): человек
читает причину и не может ничего сделать. Рецепт её требует — вид отказа у
«не загрузилось» не совпадает с видом «запрещено» (§4), и у второго кнопка
обязана быть живой.

**Перечитать на входе:** заказ целиком, на каждом входе. Состояние меняет бар,
и старое слово на экране обещает человеку то, чего уже нет: «готов» у выданного
заказа отправит его к стойке второй раз.

**Усечение:** название позиции в «Что заказано» — `.clamp1`, одна строка с
хвостом; номер заказа не усекается — им человека находят у стойки.

**Запрещено** (прибор у каждого):

| запрет | прибор |
|---|---|
| печатать `0 ฿`, когда сумма не пришла | построением: строка «Сумма» существует только при непустом `sum`. Случай батареи: `sum === null` → строки «Сумма» на экране нет |
| обещать отмену заказа членом клуба | `rg -c 'Отменить заказ' js/16-ekrany-bar.js` — замер, сегодня 1 (примечание `barCart` «Отменить заказ может только бар»); ожидание: число НЕ РАСТЁТ |
| «Отложить заказ» — сервер такого состояния не знает | `rg -c 'Отложить' js/16-ekrany-bar.js` — замер, сегодня 1, и это проза комментария `:114`; ожидание: число НЕ РАСТЁТ |
| доля, `%`, число доли клуба | `rg -c 'meter' js/16-ekrany-bar.js` — замер, сегодня 2 (полосы бара); ожидание: число НЕ РАСТЁТ |

**Признак сборки** (цель числом):
`python3 -I tools/v-oblasti.py js/16-ekrany-bar.js barOrder 'Заказ не загрузился'`
— **до сборки 0 (замер по `97da7f0`), обязано стать 1**. Признак целит в ТРЕБОВАНИЕ рецепта: вид
«не загрузилось» со своими словами и кнопкой повтора, которого на экране нет.
Признак на существование ключа `barOrder` был бы истинен в день написания.

Область признака — ЭКРАН, а не файл: семья живёт в одном `js/16-ekrany-bar.js`,
и счёт `rg -c` по файлу считает заодно работу соседей по семье (условие
прибора — `../uslovia-pribora.md`). Замер в области: `tools/v-oblasti.py`.

⚠ **Прежняя редакция (`rg -c` по файлу) была ЛОЖНЫМ ЗЕЛЁНЫМ:** на сданной
витрине счёт 1 сошёлся с целью, а находка — в помощнике `mineFail` (`:20`), в
теле `barOrder` фразы нет вовсе. В области экрана признак сходится по ДЕЛУ:
тело зовёт помощника, и прибор области идёт по вызову.

## Чего этот рецепт не несёт

Общий перечень — в `../README.md`. Отдельно по этому экрану:

<!-- РАЗВИЛКА: python3 -I tools/v-oblasti.py js/16-ekrany-bar.js barOrder 'class="steps"' → 2 0 -->

1. ⚠ **Лестница `.steps` — РАЗВИЛКА владельца, а не запрет.** В демо-ветке
   стоит лестница из пяти шагов («Отправлен на бар», «Бар принял» — «видно,
   когда работник нажмёт „Принять"», «Готовится» — «обычно 3–5 минут», «Готов»,
   «Выдан» — «заказ закрыт, строка ушла в книгу клуба»), а в живом экране её НЕТ
   вовсе. Замер в ОБЛАСТИ `barOrder`: `class="steps"` — 1 (контейнер лестницы
   в демо-ветке; пять шагов строит `.map`, контейнер один).
   Исходов два, и цифра у них разная: дописать живому — тогда станет 2; снять
   обещание из демо — тогда 0. **Признак назначается ПОСЛЕ решения**: запрет
   без прибора я не завожу, а прибор, назначенный до решения, предрешал бы его
   за владельца;
2. **Сколько минут готовится заказ** — «обычно 3–5 минут» стоит только в демо и
   ничем не подтверждено: сервер времени готовки не отдаёт;
3. **Снимок не годится доказательством** — у экрана своя демо-ветка.

⚠ **Прежние исходы развилки («4 или 0») были оба НЕВЕРНЫ, и промах мой:** я
считала `class="steps"` по файлу, получила 2 и записала оба контейнера своему
экрану. Второй — у `barShot` («Как напиток попадает в меню»), то есть у чужого
экрана, и ни одно решение владельца его не уносит. Прими владелец «дописать
живому» — счёт по файлу стал бы 3, и развилка сказала бы «не выполнено» на
верной сборке. В области экрана исходы 2 и 0. Снято замером 07.11.2026.
