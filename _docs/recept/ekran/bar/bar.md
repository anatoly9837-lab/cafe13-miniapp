# `bar` · меню бара

Рецепт ОДНОГО экрана по форме `../README.md`. Семья — `bar`, состав семьи —
`sostav.md` рядом. Экран ОТТАИВАЕМЫЙ: собран и закрыт заморозкой (`FROZEN`,
`js/02-chlenstvo.js:359`), 0.2 его открывает.

⚠ Геометрия и токены сюда НЕ переписаны: уровень класса, радиус и цвет — в
составе, значения уровней — в `../../sostav-shkaly.md`.

---

**Зритель:** член клуба — экран печатает ЕГО остаток. Своего права у функции
нет, дверь даёт вкладка **«Услуги»**. Работник бара видит то же меню:
отдельного вида для него здесь не бывает.

**Вход:** вкладка **«Услуги»** → экран `guest` → группа «Бар клуба» → строка
«Бар Café XIII» (`.listitem accent`, подпись «Кофе, чай, авторские · заказ из
приложения», `js/11-ekrany-klub.js:69`). Это ЕДИНСТВЕННАЯ живая дверь в бар: на
«Клубе» (`home`) двери нет вовсе — перемерено по `TABS`
(`js/21-navigaciya.js:226`) и по обеим веткам `guest`.

**Выход:** `drink` (строка меню), `barCart` («Оформить»), `topup` (кнопка «Не
хватает N ฿»).

⚠ **Носитель двери — экран `guest`, и он тоже выходит из заморозки вместе с
витриной:** другого живого содержимого у него нет, то есть оттаять витрину без
него значит открыть комнату с замурованным входом. Вход через «Услуги» сходится
со словом владельца (`Cafe13KPG#855`, 0.2.5): «Во вкладке „Услуги" член клуба
видит бар и его карточки в продаже».

⚠ **Слова кнопки покупки живут в помощнике `buyBtn`** (`js/21-navigaciya.js:137`),
а не на экране, и их четыре: «Отправляем…» (погашена, `BUSY`), «Бар закрыт»
(погашена при закрытой смене), «Не хватает N ฿» (ведёт на `topup`), «Купить».
Искать их в теле экрана бесполезно — это замер, а не предположение.

**Данные экрана:** `GET /directions` → направление «Бар» по НАЗВАНИЮ, не по
числу (`BAR = {id, open}`); `GET /bar/menu` → группы с позициями (`id`,
`title`, `about`, `price`, `mins`, `shot`, `photo`, `tone`); остаток — из
профиля члена.

**Состояния** — все три в живой ветке ЕСТЬ, и это на витрине редкость:

| состояние | вид и слова |
|---|---|
| загрузка | `.card quiet` → `.small` «Загружаем меню…» |
| не загрузилось | `.card strong` → `h2` «Меню не загрузилось», `p` с текстом отказа сервера, `.btn` **«Повторить»** |
| пусто | `.card quiet` → `.small` «В меню пока ни одной позиции — его заводит куратор бара.» |

⚠ **«Повторить», а не «Попробовать снова».** Одно действие — одно слово, и
расхождение измерено: в этом же файле «Повторить» стоит дважды (`:252`,
`:538`), «Попробовать снова» — один раз (`:16`, как раз здесь). По клиенту
счёт 15 против 13, то есть ни одна формулировка не победила сама. Решение
дизайнера: «Повторить» — короче и уже преобладает в семье.

**Перечитать на входе:** меню и остаток. Цена и смена меняются на баре, а
остаток решает, гаснет ли «Купить» — старое число обещало бы покупку, которой
сервер не даст.

**Усечение:** название позиции — `.clamp2` (две строки); описание позиции
(`about`) — `.clamp1` (одна строка с хвостом); название группы не усекается —
его пишет куратор и оно короткое.

**Запрещено** (прибор у каждого):

| запрет | прибор |
|---|---|
| «Купить» при закрытой смене | запрет ПОСТРОЕНИЕМ: `buyBtn` отдаёт погашенную кнопку «Бар закрыт». Случай батареи: смена закрыта → кнопки покупки нет живой |
| наличные как способ оплаты гостя | `rg -c 'наличн' js/16-ekrany-bar.js` — сегодня 2, оба законны (примечание `:155`, расход бара `:450`); ожидание: число НЕ РАСТЁТ |
| доля, `%`, число доли клуба | `rg -c 'meter' js/16-ekrany-bar.js` — сегодня 2 (полосы бара); ожидание: число НЕ РАСТЁТ |
| обещать часы работы, которых экран не знает | `rg -c 'Открыт до 23:00' js/` — сегодня 1, и это ДЕМО-ветка этого экрана; ожидание после решения владельца: 0 |

**Признак сборки** (направление — ТРЕБОВАНИЕ): `rg -c 'Попробовать снова'
js/16-ekrany-bar.js` — **сегодня 1, обязано стать 0**. Признак целит в ТРЕБОВАНИЕ рецепта, а не в существование
экрана: ключ `bar` в клиенте есть давно, и признак на него был бы истинен в
день написания рецепта.

## Чего этот рецепт не несёт

Общий перечень — в `../README.md`. Отдельно по этому экрану:

1. **Влезает ли строка меню** с длинным названием и описанием — проверяется
   отрисовкой, не текстом;
2. **Решение о демо-ветке** (`«Открыт до 23:00»`) — за владельцем; пока оно не
   принято, запрет выше назван с ожиданием, а не с приговором;
3. **Снимок этого экрана показывает ДЕМО** (вне Telegram `LIVE` ложь, а у `bar`
   своя демо-ветка), поэтому расхождение рецепта и сборки судится по разметке и
   коду, а не по картинке.
