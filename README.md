# Café XIII — клиент мини-приложения Telegram

Статический клиент клуба Café XIII (Тонгсала, Ко Пханган): личный кабинет,
пропуск, афиша мероприятий, услуги острова, касса работника.

**Репозиторий публичный намеренно.** Эту страницу скачивает браузер каждого
гостя — секретов в ней нет и быть не может. Токен бота и данные людей живут
на стороне сервера, который проверяет подпись `initData`; он приватный.

## Состояние

Сервера пока нет: данные зашиты в `app.js` (объект `DATA`), роль
переключается вручную через значок в шапке. Это демонстрация экранов, а не
работающий клуб.

Живой режим уже в коде и **выключен** (`API_ON = false` в `app.js`): клиент
ходит на `https://api.cafe13.club` с подписью `X-Telegram-Init-Data`, кабинет
берёт уровень, срок, баланс и роли из `GET /me`, согласие пишет в
`POST /me/consent`. Включается, только когда на сервере стоит список
допущенных — вместе с CORS, одной выкладкой. Вне Telegram запросов нет вовсе.
Экраны, ещё не подключённые к серверу, в живом режиме честно пишут «ещё не
подключено» вместо демонстрационных чисел.

Проверка живого режима — `tools/live.cjs` (Telegram и API подменены, к
серверу не ходит):

```bash
docker run --rm -v $PWD:/app:ro -v <каталог-снимков>:/work -w /work \
  --entrypoint node agenthost/playwright:1.59.1 /app/tools/live.cjs
```

## Опись экранов

Отдельная страница со всеми экранами — `screens.html`. Она не пишется руками:
снимки делает `tools/shots.cjs` с живой страницы, страницу и печатную версию
собирает `tools/catalog.py`.

```bash
docker run --rm -v $PWD:/app:ro -v <каталог-снимков>:/work -w /work \
  --entrypoint node agenthost/playwright:1.59.1 /work/shots.cjs
python3 tools/catalog.py <каталог-снимков>
```

`shots.cjs` — не только съёмка: он же проверяет поведение (заказ уходит с
выбранными местом и оплатой, «Принять» меняет состояние у гостя и у бара,
затрата записывается тем, что ввели) и падает, если на снимаемом экране нет
его собственного признака. Признак берётся из содержимого `#view`, а не из
шапки: шапка у разных экранов одинаковая и экраны не различает.

Версия вверху `screens.html` должна совпадать с версией в демо-режиме
приложения. Разошлись — опись устарела, пересобрать.

## Палитра — снята с места, не придумана

Фирменного цвета у заведения нет: в логотипе 244 оттенка и все ахроматические,
знак — тёплый угольный `#2B2A28` на белом. Дневные цвета взяты из интерьера
(горчичный бархат, сансевиерия, лососевая банкетка), ночные — из вечернего
света (магента, янтарь). Переключение день/ночь — свойство самого места,
поэтому тема следует за темой Telegram, а пропуск всегда ночной: его
показывают у двери вечером.

Заголовки набраны брусковым шрифтом, потому что в знаке римские цифры `XIII`
брусковые.

## Чего здесь нет

- приёма платежей: деньги принимает работник в кассе, приложение лишь
  записывает факт;
- проверки подписи `initData`: это работа сервера, в браузере она
  бессмысленна;
- настоящего кода пропуска: его выдаёт сервер, на экране демонстрационный
  узор, и так и подписано;
- фотографий напитков: на их месте цветные плитки и пометка «без фото».
  Картинку из каталога ставить нельзя — гость закажет не то, что увидел.
  Фотография появляется, когда снимок пройдёт путь с экрана «Съёмка».
